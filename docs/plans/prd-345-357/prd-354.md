# PRD 354: PRD: Public club page (/clubs/:id)

## Problem Statement

Clubs are central to play, and the data is there: courts, amenities, photos, `clubRating`, `ClubReview`, booking integration, favorites, upcoming public games. Yet there is no club destination. Club info appears only inside `ClubInfoDialog` / `ClubDetailPanel` from a game or the picker, so a club cannot be linked, shared, or browsed on its own.

## Solution

A guest-readable club page at `/clubs/:id` inside the MainPage shell: hero, address and map, courts with indoor/outdoor and surface, opening hours, amenities, booking capability badge and connect CTA, reviews with the existing write flow, upcoming public games at this club, and favorite. Deep-linkable and shareable; Find advanced filter and game details link to it.

## User Stories

1. As a player, I want to open a club from a game's location, so that I can learn about the venue.
2. As a guest with a shared link, I want to see the club and its public games, so that the page works as a landing.
3. As a player, I want to favorite the club from the page, so that Find's favorite-clubs filter is one tap away.
4. As a player, I want to read reviews and write one for a game I played there, so that reviews grow.
5. As a player, I want to see upcoming public games grouped by day with join buttons, so that the page is actionable.
6. As a player, I want a "Create game here" button that pre-fills the club in the wizard.
7. As a player, I want to connect the club's booking integration from the page when one exists.
8. As a club admin, I want a "Manage" button to my-clubs when I administer this club.
9. As a player, I want to share the club with the native share sheet.
10. As a Telegram user, I want club links to open the app page via deep link.
11. As a developer agent, I want the page composed from `ClubDetailPanel` and `ClubReviewsSection`, not a rewrite.
12. As a player, I want to see today's court availability at a glance when the club has an integration, so that I know if it is worth booking.
13. As a player, I want to see who plays here (regular players) so that a new club feels familiar.

## UX / UI Design

### Layout (top to bottom)
1. **Hero**: club photos as a swipeable gallery (first photo full-bleed, page dots), gradient overlay, club avatar overlapping the bottom edge, name, rating stars with count ("4.6 · 38 reviews"), and a sport icon row. Top-left back, top-right **Share** and **Favorite** (heart fills with a 200 ms scale bounce). The hero collapses into a compact sticky header on scroll (name + favorite), driven by scroll progress.
2. **Action row**: three equal buttons **Create game here** (primary), **Book** (visible when an integration exists: connected → opens create-game booking flow; not connected → connect sheet), **Directions** (opens maps). Club admins get a fourth **Manage**.
3. **Today at a glance** (integration clubs): a horizontal strip of court chips for today, each showing free/busy hour blocks as a small bar (green free, grey busy) from the existing occupancy snapshot, with a caption "Updated 2 min ago". Tap a court → create-game with club, court, and date prefilled.
4. **Upcoming games**: `GameCard`s grouped by day using the existing `GamesDateGroupHeading`, capped at 10 with **See all on Find** (deep-links Find with the club filter applied). Empty: "No public games yet. Be the first." with the create action.
5. **Courts**: a compact grid of court tiles (name, indoor/outdoor icon, surface, sport) using `isIndoor` and `surfaceType`; camera icon when `webCameraUrl` exists.
6. **Info**: address with mini map (`ClubMiniMap`), opening hours (today highlighted), phone/website/email as tappable rows, amenities as icon chips (reuse `ClubDetailPanel` sections), policy text collapsed under "Cancellation policy".
7. **Regulars**: avatar row of the 8 most frequent players here in the last 90 days (public profiles only), tap opens the player card.
8. **Reviews**: `ClubReviewsSection` with the star breakdown at the top and **Write a review** when the viewer has an eligible game; guests see a login prompt.

### Entry points
- `GameInfo` club name and `ClubModal` "Open club page" link; Find advanced filter club rows get a chevron; player card "Home court" chip (from the recap PRD) links here.

### Guest behavior
- Everything renders; Favorite, Create, Book, Write review prompt login with the remembered return path.

### Loading, error, offline
- Hero skeleton with a shimmering block, three card skeletons; club not found → `EmptyStateCard` "This club isn't available" with **Browse clubs**; offline → cached page from the query cache with the offline banner.

### Motion and theme
- Hero parallax at 0.3× scroll speed (off under reduced motion); section reveal on first scroll with a 12 px lift; premium members see gold rating stars.

### Accessibility
- Gallery is a `role="region"` with keyboard paging; rating exposed as text; court tiles have full labels ("Court 3, indoor, artificial grass").

## Implementation Decisions

- Route `/clubs/:id` in `App.tsx` rendered by `MainPage` (overlay-capable like `/user-profile/:userId`), no `ProtectedRoute`. Offline gate exception like game details.
- API: `GET /clubs/:id/public` (optionalAuth) → club, courts, integration capability, review summary, `isFavorite`, `isAdmin`, hours; `GET /clubs/:id/regulars` (90-day PLAYING counts, public profiles only, cached 10 min). Upcoming games via `useAvailableUpcomingGames` with `clubIds=[id]`. Today occupancy via the existing per-club snapshot endpoints (Booktime/Padeloo/Klikteren) and `/nspadel/*` availability, read-only.
- Components: `ClubPage` composing `ClubAvatar`, `ClubMiniMap`, `ClubBookingBadge`, `ClubDetailPanel`, `ClubReviewsSection`; new `ClubHeroGallery`, `ClubTodayStrip`, `ClubCourtsGrid`, `ClubRegularsRow`.
- Links: deep link catalog entry `/clubs/:id` in `deepLinks/catalog.ts` and `useDeepLink.ts`; Telegram game messages link the club name.
- Create prefill: `/create-game?clubId=&courtId=&date=` (extend `parseCreateGameDeepLinkSearch`).
- Share: `ShareModal` with the club URL.
- Find filter deep link: `/find?clubIds=` handled by `useFindFromUrl`.

## Testing Decisions

- API test: guest projection hides nothing sensitive; `isAdmin`, `isFavorite`, regulars privacy filter.
- FE: guest vs authed actions, admin button, prefill navigation, sticky header, gallery paging, empty games state.
- Deep link route test; Find club filter from URL.
- UI test plan: Club page section.

## Out of Scope

- Club-authored posts or news feed.
- Court pricing tables beyond `pricePerHour` display.
- Editing club data from the public page.

## Design language (shared with every PRD in this set)

- **Mobile first.** Capacitor iOS/Android and mobile browsers are the primary target. Every overlay with an input lays out against the visual viewport via the keyboard contract (`Frontend/src/utils/keyboardLayout.ts`, `body.keyboard-visible`, `--overlay-bottom-inset`). Desktop gets the same components in the split layouts already used by Home/Find.
- **Surfaces.** Bottom sheets (vaul) for actions and detail, Radix dialogs only for destructive confirms, full-screen routes for destinations. Sheets open/close with the existing `[data-state='open'|'closed']` keyframes; all motion gated on `prefers-reduced-motion`.
- **Motion.** Framer Motion 12. Springs for entrance (stiffness 260, damping 24), 180–240 ms fades for state changes, layout animations for list reorders. Never animate more than one hero element at once. Number changes use a count-up tween ≤600 ms.
- **Color.** Tailwind `primary` (sky) for actions, semantic greens/ambers/reds for states, neutral surfaces from `tokens.css`. Premium members keep gold accents where the shell already applies them; new surfaces must read correctly in Light, Dark, Classic, and Premium.
- **Type and density.** One headline per screen, one primary action per sheet, secondary actions as text buttons. Cards keep the `GameCard` rhythm: date tile left, title row, info rows, right rail.
- **Icons.** lucide-react only. No emoji as icons; emoji allowed in copy where playful.
- **Feedback.** `react-hot-toast` for transient confirmations, inline banners for persistent state, skeletons (`GameCardSkeleton` pattern) for loading, `EmptyStateCard` for empties with one clear next action.
- **Accessibility.** 44 px tap targets, 4.5:1 text contrast, roles/labels on every control, arrow-key support on segmented controls, RTL verified for `ar`, all copy in the 11 app locales.
- **Copy.** Plain, second person, verbs first ("Confirm seat", not "Seat confirmation"). No jargon from the schema in user-facing text.
