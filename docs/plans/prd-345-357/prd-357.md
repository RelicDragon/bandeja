# PRD 357: PRD: Weather alerts for outdoor games

## Problem Statement

Weather is fetched per game and shown in calendar cells and a details dialog, and `Court.isIndoor` already exists, but nothing proactive happens. A rained-out outdoor game is discovered on arrival or by someone checking the dialog.

## Solution

A weather check 12 hours before start for games on outdoor courts. When precipitation probability or wind crosses a threshold, participants get one **weather alert** push with the forecast and quick actions for the organizer: move indoor (edit courts), reschedule (edit time), or keep. Cards show a rain badge for at-risk games.

## User Stories

1. As a participant in an outdoor game, I want a push 12h before if rain is likely, so that I can plan.
2. As an organizer, I want the alert to deep-link into edit location and time, so that fixing it is quick.
3. As an organizer, I want a "Keep as planned" action that silences further alerts for this game.
4. As a participant, I want a rain badge on the card on Home and Find, so that risk is visible at a glance.
5. As a participant, I want an indoor game to never alert, so that noise stays low.
6. As a participant, I want a second alert 2h before only if the forecast got worse, so that I am not spammed.
7. As a user, I want to mute weather alerts in notification prefs.
8. As a club admin, I want courts marked indoor/outdoor correctly, so that alerts are accurate.
9. As a developer agent, I want thresholds as constants and the check to run inside the existing status scheduler cadence.
10. As an organizer, I want a one-tap "Move indoor" that shows free indoor courts at the same club and time, so that rescuing a game takes seconds.
11. As a participant, I want a quick poll in game chat "Play in light rain?" that the organizer can post from the alert, so that the group decides fast.

## UX / UI Design

### Alert push
- Title "Rain likely for tomorrow's game ☔" body "70 % chance of rain at 19:00, Padel Centar court 3 (outdoor)". Organizer actions: **Move indoor**, **Keep as planned**. Participant action: **View forecast**.

### Game details: Weather risk banner
- For at-risk games, a banner under the header in amber (rain) or slate (wind): weather icon, "Rain likely · 70 % at 19:00", a small hourly strip of 4 icons around start time, and, for organizers, three chips **Move indoor · Change time · Keep as planned**. Participants see **Forecast** which opens the existing `GameWeatherDialog`.
- **Move indoor** opens a sheet listing indoor courts at the club with availability for the game window (from the occupancy service): each row shows court name, "Free" in green or "Busy", and tapping a free court applies the court change through the existing edit path, posts a system message "Moved to court 1 (indoor)", and dismisses the banner with a 240 ms collapse. If no indoor court is free: "No indoor courts free at 19:00" with **Change time** as the fallback.
- **Change time** opens `EditGameInfoModal` on the time section.
- **Keep as planned** collapses the banner to a single grey line "Playing rain or shine ✓" and suppresses the 2 h alert; organizers can also tap **Ask the group** which posts a chat poll "Play in light rain?" with Yes/No using the existing poll message type.

### Cards
- `GameCardHeaderTags` gets a weather pill: rain drop icon with the percentage ("70 %") in amber, or wind icon with km/h in slate, only for outdoor games within 48 h that cross the threshold. Tooltip on long-press "Forecast for 19:00". After "Keep as planned", the pill turns neutral grey.
- Calendar day cells already show weather; no change.

### Notification preferences
- New row **Weather alerts** in `NotificationSettingsModal` under reminders, with the helper "Only for outdoor courts".

### Club admin
- Courts CRUD form: the indoor/outdoor control becomes a prominent `SegmentedSwitch` **Indoor · Outdoor** with an icon, and the schedule grid shows a small roof icon on indoor court headers, so admins notice wrong values.

### Edge cases
- Courts unknown: no alert, no pill.
- Forecast unavailable: nothing shown; never a "no data" banner.
- Second alert only if severity class rises (e.g., 60 % → 85 % or rain → storm); copy "Forecast got worse: 85 %".
- Multi-court games: at-risk if any selected court is outdoor; "Move indoor" handles one court at a time with a count "1 of 2 courts outdoor".

### Motion and theme
- Banner appears with a 200 ms fade and the hourly icons stagger in 40 ms each; collapse on resolution. Amber and slate tokens have dark-mode variants; premium theme unchanged.

### Accessibility
- Pill reads "Rain likely, 70 percent at 19:00"; banner chips are buttons; the sheet rows announce availability.

## Implementation Decisions

- Outdoor detection: any linked `GameCourt`/`Game.court` with `isIndoor === false`; games without courts use the club's active courts majority; unknown → no alert.
- Data: `weatherForecast.service.ts` hourly for the game window (cached in `WeatherForecastCache`). Thresholds (constants in `weatherRisk.ts`): precipitation probability ≥60 % or ≥1 mm/h in the window, wind ≥40 km/h. Severity classes: none / likely / heavy / storm.
- Scheduler step in `GameStatusScheduler` (:00/:30) evaluates games with `timeIsSet`, status ANNOUNCED, start in 11.5–12.5 h (first) and 1.5–2.5 h (second, only if severity class increased). Store `Game.weatherAlertState` JSON `{ severity, sentAt[], keepAsPlannedAt?, lastEvaluatedAt }`.
- `NotificationType.GAME_WEATHER_ALERT` → new pref key `sendWeatherAlerts` (default true), push + Telegram; organizer and participant copy variants; actions via invite-action tokens (`WEATHER_KEEP`) and deep links `?section=weather&action=moveIndoor`.
- Move indoor: `GET /games/:id/indoor-alternatives` → free indoor courts for the window from `CourtOccupancyService.getOccupancy`; apply through the existing court update path in `update.service.ts` (linked external bookings are not changed; the response warns when a booking is linked to the outdoor court).
- Card projection: `weatherRisk { severity, pop, windKph, at }` for outdoor games within 48 h, computed from the cached forecast in `availableGamesEnrichment.ts` and the my-tab payload.
- Poll: reuse `POLL` message creation with fixed options.
- Club admin: reuse existing `isIndoor` field; provider court import maps indoor flags where Booktime/Padeloo expose them.

## Testing Decisions

- Pure severity and outdoor-detection tests.
- Scheduler tests with fixed clock: first/second alert windows, severity escalation rule, keep-as-planned suppression, indoor exclusion, multi-court.
- Indoor alternatives service test against occupancy fixtures.
- Notification pref mapping test; token action test.
- FE: banner variants, move-indoor sheet states, card pill, prefs row, admin courts switch.
- UI test plan: card badge, banner actions, organizer actions from push (manual).

## Out of Scope

- Automatic rescheduling.
- Weather for EVENT listings.
- Historical weather on results (archive already exists).

## Design language (shared with every PRD in this set)

- **Mobile first.** Capacitor iOS/Android and mobile browsers are the primary target. Every overlay with an input lays out against the visual viewport via the keyboard contract (`Frontend/src/utils/keyboardLayout.ts`, `body.keyboard-visible`, `--overlay-bottom-inset`). Desktop gets the same components in the split layouts already used by Home/Find.
- **Surfaces.** Bottom sheets (vaul) for actions and detail, Radix dialogs only for destructive confirms, full-screen routes for destinations. Sheets open/close with the existing `[data-state='open'|'closed']` keyframes; all motion gated on `prefers-reduced-motion`.
- **Motion.** Framer Motion 12. Springs for entrance (stiffness 260, damping 24), 180–240 ms fades for state changes, layout animations for list reorders. Never animate more than one hero element at once. Number changes use a count-up tween ≤600 ms.
- **Color.** Tailwind `primary` (sky) for actions, semantic greens/ambers/reds for states, neutral surfaces from `tokens.css`. Premium members keep gold accents where the shell already applies them; new surfaces must read correctly in Light, Dark, Classic, and Premium.
- **Type and density.** One headline per screen, one primary action per sheet, secondary actions as text buttons. Cards keep the `GameCard` rhythm: date tile left, title row, info rows, right rail.
- **Icons.** lucide-react only. No emoji as icons; emoji allowed in copy where playful.
- **Feedback.** `react-hot-toast` for transient confirmations, inline banners for persistent state, skeletons (`GameCardSkeleton` pattern) for loading, `EmptyStateCard` for empties with one clear next action.
- **Accessibility.** 44 px tap targets, 4.5:1 text contrast, roles/labels on every control, arrow-key support on segmented controls, RTL verified for `ar`, all copy in the 11 app locales.
- **Copy.** Plain, second person, verbs first ("Confirm seat", not "Seat confirmation"). No jargon from the schema in user-facing text.
