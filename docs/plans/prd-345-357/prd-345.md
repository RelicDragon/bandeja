# PRD 345: PRD: Recurring game series (weekly regulars)

## Problem Statement

Weekly regulars are the backbone of club play, but Bandeja has no recurrence concept. Every week an organizer re-creates the same game via Duplicate (`buildDuplicateGameInitialData`), re-invites the same people, and re-books the court. Nothing links the weeks together, so there is no roster carry-over, no "same time next week" prompt, and no series-level history.

## Solution

Add a **Game series**: an organizer-owned recurrence that spawns one ordinary `Game` per occurrence. Each occurrence is a normal `GAME` / `TRAINING` / `TOURNAMENT` row with all existing rules (roster, results, rating, booking). The series holds the template (format, club, courts, weekday, time, duration, level band, price, settings) and the **regular roster**. After each occurrence finishes, PLAYING participants get a one-tap "I'm in for next week" that pre-seats them in the next occurrence. Occurrences are generated a fixed horizon ahead, never all at once.

## User Stories

1. As an organizer, I want a "Repeat weekly" toggle on create-game, so that my regular game exists for future weeks without re-entering it.
2. As an organizer, I want to choose weekly or every-two-weeks and an optional end date, so that seasonal regulars stop on their own.
3. As an organizer, I want the next occurrence created automatically N days ahead, so that Find and My show it before people plan their week.
4. As an organizer, I want to edit the series template and choose "this occurrence only" or "this and future", so that a one-off venue change does not rewrite history.
5. As an organizer, I want to skip one occurrence (holiday) without ending the series.
6. As an organizer, I want to end a series, keeping past occurrences and deleting only future unstarted ones with no results.
7. As a regular, I want a "Same time next week?" prompt after a finished occurrence, so that I keep my seat in one tap.
8. As a regular, I want to be pre-seated as PLAYING in the next occurrence when I confirm, so that I never lose my spot to a newcomer.
9. As a regular who does not confirm by a deadline, I want my seat released to the queue/public, so that games fill.
10. As a newcomer, I want to see "Weekly · Tuesdays 19:00" on the card and details, so that I understand this is a recurring group.
11. As a participant, I want the series page to show past occurrences, attendance count, and win rate within the series.
12. As a participant, I want the game chat to be per occurrence (unchanged) plus an optional series group chat, so that long-running discussion has a home.
13. As a player using booking integrations, I want each occurrence to carry its own booking link, so that court coverage badges stay accurate per date.
14. As a player, I want game subscriptions and play intents to match occurrences like any public game, so that series are discoverable.
15. As an admin, I want a cap on how many active series a user owns, so that abuse stays bounded.
16. As a developer agent, I want occurrence generation to be idempotent per (seriesId, occurrenceDate), so that scheduler retries do not duplicate games.
17. As an organizer, I want to convert an existing one-off game into a series from its settings, so that I do not recreate a game that already has a roster.
18. As a regular, I want to leave the regular roster without leaving the current game, so that "not next week" and "not tonight" are separate choices.

## UX / UI Design

### Entry points
- **Create game → Scheduling**: after Date and Time, a new row **Repeat** with a `SegmentedSwitch` `Once · Weekly · Every 2 weeks`. Selecting a cadence reveals a compact summary line under the switch: "Every Tuesday at 19:00, from 24 Sep" with an optional **Until** date chip (opens the existing date picker). The floating `CreateGameSummaryBar` gains a small `Repeat` chip so the choice stays visible while scrolling.
- **Game details → Settings**: a **Make this a weekly game** row for one-off games (owner only, `resultsStatus === NONE`). Opens the same Repeat sheet prefilled from the game.
- **Cards** (Home, Find, chat game cards): a slim pill in `GameCardHeaderTags` reading `↻ Weekly` in neutral tone. The date tile is unchanged so cards remain scannable.
- **Series page** `/series/:id`: reachable from the pill on any occurrence, from the series chat, and from Profile → Statistics → "Your regular games".

### Repeat sheet (organizer)
Bottom sheet, 60% height, title "Repeat this game". Contents top to bottom: cadence segmented switch; weekday chips (pre-selected from the date, editable for biweekly offsets); time (read-only, edits go through the normal time picker); **Until** date chip; **Regulars** section listing current PLAYING players with avatars and a toggle per player "Keep as regular" (default on); a **Seat deadline** stepper "Release unclaimed seats 48 h before" (24 / 48 / 72). Primary button "Save series". A single-line helper under the button: "We create the next game 14 days ahead. You can skip or end any time."

### Occurrence details
- Under the title, a quiet line "Part of *Tuesday Regulars* · 12th week" linking to the series page.
- **Organizer strip** (owner/admin, only when a next occurrence exists): "Next: Tue 1 Oct · 3 of 4 regulars confirmed" with avatars showing check badges, and two text buttons **Skip next** and **Edit series**. Confirmations update live via the `game-{id}` room and animate the check badge with a 200 ms scale spring.
- Edit flows from `EditGameInfoModal` append a scope choice sheet: "Apply to · This game · This and future games" with a one-line note listing occurrences that will be skipped because results already started.

### "Same time next week?" moment (regular)
- **Push** (24 h and 2 h reminders unchanged). After the occurrence reaches FINAL/FINISHED, a push "Same time next week? Tue 1 Oct 19:00 at Padel Centar" with shade actions **I'm in** and **Not this time**.
- **In-app**: a full-width card at the top of the game details and on Home MyGamesSection for the finished occurrence: left the club avatar, center "Same time next week?", right two buttons **I'm in** (primary) and **Skip**. Tapping **I'm in** morphs the button into a green check with the text "You're in for Tue 1 Oct" and the card collapses after 1.2 s. Toast: "Seat kept".
- **Not this time** asks nothing more; the seat opens at the deadline. A small note "Your seat opens to others on Sun 29 Sep" appears in the card footer.

### Series page
- **Hero**: club photo backdrop with a subtle gradient, series name, cadence line, next occurrence tile (date tile + Join/Confirmed state) and a **Regulars** avatar stack with confirmation checks.
- **Tabs** (`SegmentedSwitch`): **Upcoming** (next 4 occurrences as `GameCard`s), **History** (past occurrences with result chips, attendance % per regular), **Regulars** (list with games played, win rate inside this series, remove/add for organizer).
- **Stats band** between hero and tabs: three stat tiles Games · Your win rate · Streak of weeks, using count-up numbers on first paint.
- Empty history: `EmptyStateCard` with "First week coming up" and the next date.

### States and edge cases
- Loading: skeleton hero and three card skeletons.
- Series ended: hero shows a neutral "Ended on 30 Nov" ribbon; no confirmation prompts; History still browsable.
- Owner cap reached: the Repeat switch disables Weekly/Biweekly with a helper "You have 10 active series. End one to add another." and a link to Profile.
- Skipped occurrence: shown in Upcoming as a dimmed row "Skipped · 8 Oct" with an **Undo** text button until generation catches up.
- Offline: confirm action queues through the existing mutation queue and shows the pending outline state.

### Accessibility and localization
- Cadence and scope switches support arrow keys; every avatar in the regulars stack has a name label.
- Copy keys under a new `series` namespace; weekday and date formatting via the user's locale and week start.

## Implementation Decisions

- Schema: `GameSeries` (ownerId, name, entityType, cadence WEEKLY|BIWEEKLY, weekday, startTimeLocal, durationMinutes, clubId, courtIds, template JSON copied from create payload, horizonDays default 14, seatDeadlineHours default 48, endsOn?, status ACTIVE|ENDED, createdAt). `GameSeriesRegular` (seriesId, userId, addedAt, removedAt?). `Game.seriesId` nullable FK + `Game.seriesOccurrenceDate` (date). Unique `(seriesId, seriesOccurrenceDate)`. `GameSeriesSkip` (seriesId, occurrenceDate).
- Do not reuse `parentId`; that hierarchy means league season → fixture and drives permissions in `parentGamePermissions.ts`.
- Generation: `GameSeriesScheduler` (daily 03:30 and on series create/edit) calls `GameCreateService.createGame` with the template so every validation (`validateGameForSport`, overlap, booking) runs unchanged. Booking on generated occurrences is not auto-reserved; the card shows the existing "not booked" badge and the owner books from edit.
- Carry-over: on occurrence FINAL/FINISHED, send `GAME_SERIES_NEXT_PROMPT` (new `NotificationType`, pref key `sendInvites`) to PLAYING regulars with an invite-action token (reuse `pushInviteActionToken.service.ts`, new kind `SERIES_CONFIRM`). Confirm creates a PLAYING `GameParticipant` on the next occurrence with `invitedByUserId = series owner`; decline sets nothing. Deadline = occurrence start minus `seatDeadlineHours`; unclaimed regular seats remain open (no auto-invite).
- Convert existing game: `POST /games/:id/series` builds the template from the game and seats current PLAYING as regulars.
- Edit scope "this and future" rewrites the template and re-applies to unstarted occurrences with `resultsStatus === NONE`; locked occurrences are skipped and returned in the response for the UI note.
- End series: sets `status=ENDED`, deletes future occurrences through `GameDeleteService` (which already refuses games with results or children).
- Series chat: optional `GroupChannel` created on first "Open series chat" tap by the owner, linked by `GroupChannel.seriesId`.
- Series page data: `GET /series/:id` (occurrences, regulars, stats from existing `GameOutcome` rows). Stats are computed on read with a 60 s cache; no new materialization.
- Discovery: generated public games flow through `GameSubscriptionService` and play-intent matching unchanged.
- Owner cap 10 active series (constant `MAX_ACTIVE_SERIES_PER_USER`).
- Feature flag `VITE_GAME_SERIES_ENABLED` and backend `GAME_SERIES_ENABLED`.

## Testing Decisions

- Unit: occurrence date math across DST and club timezone (reuse timezone helpers from `utils/gameStatus.ts`), horizon fill, idempotent generation, edit-scope partitioning, skip handling.
- Service: carry-over seat creation, deadline release, end-series deletion respects `resultsStatus !== NONE`, convert-existing seats regulars, cap enforcement.
- Integration: scheduler run creates exactly one game per missing occurrence; subscription matcher fires for generated public games; push action token round-trip.
- FE: Repeat switch round-trip in create, summary chip, card pill, organizer strip live update, "Same time next week" card states, series page tabs. Add rows to `docs/UI_TEST_PLAN.md` under Create, Game details, and a new Series section.

## Out of Scope

- Auto-booking courts for future occurrences.
- Recurring leagues, events, or bar meetups.
- Series-level rating or standings (occurrences rate individually as today).
- Payment collection (see cost split PRD).

## Design language (shared with every PRD in this set)

- **Mobile first.** Capacitor iOS/Android and mobile browsers are the primary target. Every overlay with an input lays out against the visual viewport via the keyboard contract (`Frontend/src/utils/keyboardLayout.ts`, `body.keyboard-visible`, `--overlay-bottom-inset`). Desktop gets the same components in the split layouts already used by Home/Find.
- **Surfaces.** Bottom sheets (vaul) for actions and detail, Radix dialogs only for destructive confirms, full-screen routes for destinations. Sheets open/close with the existing `[data-state='open'|'closed']` keyframes; all motion gated on `prefers-reduced-motion`.
- **Motion.** Framer Motion 12. Springs for entrance (stiffness 260, damping 24), 180–240 ms fades for state changes, layout animations for list reorders. Never animate more than one hero element at once. Number changes use a count-up tween ≤600 ms.
- **Color.** Tailwind `primary` (sky) for actions, semantic greens/ambers/reds for states, neutral surfaces from `tokens.css`. Premium members keep gold accents where the shell already applies them; new surfaces must read correctly in Light, Dark, Classic, and Premium.
- **Type and density.** One headline per screen, one primary action per sheet, secondary actions as text buttons. Cards keep the `GameCard` rhythm: date tile left, title row, info rows, right rail.
- **Icons.** lucide-react only. No emoji as icons; emoji allowed in copy where playful.
- **Feedback.** `react-hot-toast` for transient confirmations, inline banners for persistent state, skeletons (`GameCardSkeleton` pattern) for loading, `EmptyStateCard` for empties with one clear next action.
- **Accessibility.** 44 px tap targets, 4.5:1 text contrast, roles/labels on every control, arrow-key support on segmented controls, RTL verified for `ar`, all copy in the 11 app locales.
- **Copy.** Plain, second person, verbs first ("Confirm seat", not "Seat confirmation"). No jargon from the schema in user-facing text.
