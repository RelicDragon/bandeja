# PRD 349: PRD: Live now rail and live-start notifications

## Problem Statement

Live scoring, TV mode, and public broadcast pages exist, but there is no way to discover them. A game in progress looks identical to any other card on Find. Followers never learn that someone they follow is on court right now.

## Solution

Surface in-progress games. Add a **Live now** rail on Find and Home for home-city games with `resultsStatus === IN_PROGRESS`, with live score chips and a tap into the broadcast view (spectator token for public games). Push followers when a followed player's rated match goes live, opt-in.

## User Stories

1. As a Find user, I want a "Live now" rail above the calendar when any public home-city game is in progress, so that I can watch.
2. As a viewer, I want the card to show current set score and court, updating live, so that it feels alive.
3. As a viewer, I want tapping the card to open the broadcast page without needing to be a participant, so that spectating is one tap.
4. As a participant in a private game, I do not want it on the rail, so that privacy holds.
5. As a follower, I want an opt-in push "X is playing live at Club Y", so that I can follow friends.
6. As a player, I want a per-game "Hide from live rail" toggle, so that I control exposure.
7. As a Home user, I want the rail only when I have no game today, so that Home stays about me.
8. As a Telegram user, I want `/live` to list live city games with broadcast links.
9. As a developer agent, I want rail data served from the existing available-games query with an `inProgress` filter, not a new store.
10. As a viewer, I want a "Live" section in the game details of an in-progress game with a big Watch button, so that arriving via a link also works.
11. As a league follower, I want live fixtures of seasons I follow to appear first.

## UX / UI Design

### Live now rail
- **Placement**: Find, above the calendar (desktop: top of the games column). Home: after `HomeActionGrid`, only when the viewer has no own game today. Hidden when empty; appears with a 240 ms height/opacity reveal.
- **Header**: a red "● LIVE" dot with a slow 2 s breathing opacity (static under reduced motion), the label "Live now" and a count "3".
- **Cards**: horizontal snap carousel of 240 px cards. Each card: club avatar + court name top-left, a **score block** center in large tabular numerals (sets as small pills, current game score large), the two sides shown as 2-avatar stacks with names, and a footer "Started 23 min ago". Rated games show the tiny rating icon. Score changes animate with a 200 ms vertical slide of the digit that changed and a brief 400 ms glow on the leading side.
- **Tap**: opens `/games/:id/broadcast` with a spectator token; a `layoutId` shared-element transition scales the score block into the broadcast header.
- **One live game**: full-width card variant with a **Watch** button on the right.

### Broadcast page entry
- Broadcast page gets a slim top bar for spectators: back, "Live · Padel Centar · court 3", and a **Follow players** overflow to follow any side's players (existing follow API).

### Game details
- For in-progress public games a **Live** block replaces the results entry area for non-participants: score summary and a large **Watch live** primary button; participants keep their existing scoring entry.

### Follower push
- "Ana is playing live at Padel Centar" with **Watch** action → broadcast; one per game.

### Settings and privacy
- `GameSettings` toggle **Show on Live now** (default on for public games). Private games never appear. Helper: "Public games in progress can be watched by anyone in your city."

### Home variant
- Same rail with a softer header "Live in Belgrade" and at most 3 cards, plus a **See all on Find** text link.

### Empty, loading, error
- Rail absent when no games; on Find, when the user has a game in progress, their own game shows first with a "You" tag.
- Loading skeleton: two score-card skeletons with shimmering digits.
- Socket loss: card shows a small grey "Reconnecting" caption; scores freeze rather than vanish.

### Accessibility
- Score block reads "Marko and Ana lead 6–4, 3–2"; live dot is decorative; the carousel is keyboard scrollable with arrow keys.

## Implementation Decisions

- Query: `useAvailableGames` variant `liveOnly` → `availableGamesStructuralWhere` adds `resultsStatus = IN_PROGRESS AND isPublic AND showOnLiveRail`. Cap 10 on Find, 3 on Home. Sort: followed-season fixtures first, then start time.
- Score payload: card projection includes a compact `liveSummary` (per active match: sides, sets, current game) from `matchLiveScoring.service.ts`; updates via the existing `game-{id}` socket room events the live board already emits. Rail subscribes only to visible cards.
- Spectator token: reuse the public broadcast token mint used by `GameBroadcastRoute`; the rail opens the URL with `?spectatorToken=`.
- Follower push: `NotificationType.FOLLOWED_USER_LIVE` → `sendPlayIntentSocialNotifications`, fired once per game when `resultsStatus` becomes IN_PROGRESS for a public game; dedupe via delivery table keyed (userId, gameId).
- `GameSettings.showOnLiveRail` boolean default true.
- FE: `LiveNowRail` component beside `FindCityEventsRail`; `LiveScoreCard`; Home placement gated by the my-tab payload "has game today".
- Telegram `/live` command lives in the Telegram PRD; this PRD provides the query.

## Testing Decisions

- Query tests for the live filter, privacy gate, sort order.
- Socket subscription lifecycle test (subscribe on mount, unsubscribe on unmount, reconnect caption).
- Notification dedupe test at IN_PROGRESS transition.
- FE: rail reveal, single vs multi card variants, score animation under reduced motion.
- UI test plan: Find rail, broadcast open as guest, Home gating, settings toggle.

## Out of Scope

- Video streaming.
- Betting integration on the rail.
- League standings live updates (already recalc on FINAL).

## Design language (shared with every PRD in this set)

- **Mobile first.** Capacitor iOS/Android and mobile browsers are the primary target. Every overlay with an input lays out against the visual viewport via the keyboard contract (`Frontend/src/utils/keyboardLayout.ts`, `body.keyboard-visible`, `--overlay-bottom-inset`). Desktop gets the same components in the split layouts already used by Home/Find.
- **Surfaces.** Bottom sheets (vaul) for actions and detail, Radix dialogs only for destructive confirms, full-screen routes for destinations. Sheets open/close with the existing `[data-state='open'|'closed']` keyframes; all motion gated on `prefers-reduced-motion`.
- **Motion.** Framer Motion 12. Springs for entrance (stiffness 260, damping 24), 180–240 ms fades for state changes, layout animations for list reorders. Never animate more than one hero element at once. Number changes use a count-up tween ≤600 ms.
- **Color.** Tailwind `primary` (sky) for actions, semantic greens/ambers/reds for states, neutral surfaces from `tokens.css`. Premium members keep gold accents where the shell already applies them; new surfaces must read correctly in Light, Dark, Classic, and Premium.
- **Type and density.** One headline per screen, one primary action per sheet, secondary actions as text buttons. Cards keep the `GameCard` rhythm: date tile left, title row, info rows, right rail.
- **Icons.** lucide-react only. No emoji as icons; emoji allowed in copy where playful.
- **Feedback.** `react-hot-toast` for transient confirmations, inline banners for persistent state, skeletons (`GameCardSkeleton` pattern) for loading, `EmptyStateCard` for empties with one clear next action.
- **Accessibility.** 44 px tap targets, 4.5:1 text contrast, roles/labels on every control, arrow-key support on segmented controls, RTL verified for `ar`, all copy in the 11 app locales.
- **Copy.** Plain, second person, verbs first ("Confirm seat", not "Seat confirmation"). No jargon from the schema in user-facing text.
