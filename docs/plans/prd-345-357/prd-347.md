# PRD 347: PRD: Spot-opened alerts and queue auto-fill

## Problem Statement

When a PLAYING participant leaves a full game, the seat opens silently. Queued players are not told, followers are not told, and people with a matching play intent only learn about the game if the intent matcher happens to run. Organizers refill by hand in chat.

## Solution

Treat a freed PLAYING seat as an event. Notify, in priority order: the game queue, users whose OPEN play intent fits the game, and followers of participants. Optionally let the organizer enable **auto-fill**: the first queued player is promoted to PLAYING immediately and everyone is told.

## User Stories

1. As a queued player, I want a push the moment a seat opens, with a "Join now" deep link, so that I get in first.
2. As an organizer, I want an "Auto-fill from queue" setting, so that the first in line is seated without my intervention.
3. As an auto-filled player, I want a notification that I am now playing, so that I do not miss it.
4. As a player with an OPEN play intent that fits this game, I want a "spot opened" notification even if I was not queued.
5. As a follower of someone in the game, I want an opt-in "friends' game has a spot" notification.
6. As an organizer, I want a system message in game chat when a seat opens and when it is filled.
7. As a player, I want at most one spot-opened notification per game per day, so that churny rosters do not spam me.
8. As an organizer, I want auto-fill to respect gender and level gates exactly like manual accept.
9. As a developer agent, I want spot-opened to be queued and deduped like play-intent delivery, not fire-and-forget.
10. As a Find user, I want games with a just-opened seat to stand out for a short while, so that I can grab them.
11. As a queued player, I want to see my position in the queue and whether auto-fill is on, so that waiting is predictable.

## UX / UI Design

### Notification
- Push title "A spot just opened" body "Tue 19:00 · Padel Centar · level 3.5–4.5. You're #1 in the queue." Action **Join now** deep-links to the game with `?join=1`, which triggers the normal join flow (gates and overlap confirm apply). Follower variant: "Marko's game has a free spot tonight".
- Telegram mirror with the existing Join callback.

### Find and Home cards
- A **"Spot opened"** pill in `GameCardHeaderTags`, sky-tinted with a tiny pulsing dot (two 1.2 s cycles, then static; static under reduced motion), shown for 2 h after the last seat-opened event. Cards with this pill sort to the top of their day group during that window.
- The join button gets a subtle shimmer once on first paint of the pill (240 ms).

### Game details
- **Queue panel** (for anyone in the queue): "You're #2 of 3 · Auto-fill is on, you'll be seated automatically" or "…Organizer accepts manually". Position updates live.
- **Organizer settings**: in `GameSettings`, a toggle **Auto-fill from queue** with helper "First in line is seated when a spot opens. Gender and level rules still apply." Below it, a read-only line "3 in queue".
- **Roster**: when a seat opens, the empty slot renders as a dashed outline slot with the text "Open spot" and a 400 ms fade-in; when auto-filled, the new avatar slides in from the queue row with a layout animation, and a toast "Ana joined from the queue" appears for the organizer.
- **Chat system messages**: "A spot opened (Luka left)" and "Ana was seated from the queue" in the neutral system style.

### Auto-filled player
- Push "You're in! Tue 19:00 at Padel Centar" and on open the game details show a one-time confetti-free highlight: the attendance card (from the attendance PRD) with a green header "You were seated from the queue".

### Empty and edge states
- No queue and auto-fill on: settings helper reads "No one waiting yet".
- Locked roster (`resultsStatus !== NONE`): pill never shown, no notifications.
- Private game: notifications only to queue members.

### Accessibility
- Pill has `aria-label="A spot opened two minutes ago"` with a relative time; pulse is decorative.

## Implementation Decisions

- Trigger points: `leaveGame`, `kickUser`, decline of a PLAYING invite, substitution rollback, and `maxParticipants` increase in `update.service.ts`. Each calls `GameSeatService.seatOpened(gameId, freedCount, cause)`; the service records `Game.lastSeatOpenedAt`.
- New `NotificationType.GAME_SPOT_OPENED` → pref key `sendInvites`; follower variant `FOLLOWED_GAME_SPOT_OPENED` → `sendPlayIntentSocialNotifications`.
- Auto-fill: `GameSettings.autoFillFromQueue` boolean. Promotion reuses `acceptJoinQueue` (same gates, play-intent consume, existing accepted message). Only when `resultsStatus === NONE` and `canMutateGameRoster`. Queue order = `joinedAt`. If the first queued fails a gate, try the next; if none, fall through to notifications.
- Recipient sets: queue members (not seated), intent fits via `PlayIntentMatchJob` scoring against the single game, followers of PLAYING participants (opt-in pref). Dedupe with `PlayIntentNotificationDelivery` extended by kind `SPOT_OPENED` keyed (userId, gameId, dayKey).
- Card projection: `availableGamesCard.projection.ts` adds `spotOpenedAt` when within 2 h; sort tweak in the FE day grouping only.
- Deep link `?join=1` handled in `GameDetailsPage` to invoke the existing join handler after load.
- Socket: `game:seat-opened` and `game:seat-filled` on `game-{id}`.
- Rate limit: one notification per (userId, gameId, dayKey).

## Testing Decisions

- Service: each trigger emits once; auto-fill promotes exactly one and respects gates and fallback; no promotion when locked; dedupe per day; owner excluded.
- Integration: leave → queue push → join succeeds via `?join=1`; intent recipient set equals matcher output; follower pref off yields no send.
- FE: settings toggle, pill timing, queue panel position, roster slide-in, chat system messages.
- UI test plan: queue flow, auto-fill row, Find pill.

## Out of Scope

- Paid priority in queue.
- Cross-city matching.
- Changing the existing NEW_GAME or GAME_MATCHES_INTENT semantics.

## Design language (shared with every PRD in this set)

- **Mobile first.** Capacitor iOS/Android and mobile browsers are the primary target. Every overlay with an input lays out against the visual viewport via the keyboard contract (`Frontend/src/utils/keyboardLayout.ts`, `body.keyboard-visible`, `--overlay-bottom-inset`). Desktop gets the same components in the split layouts already used by Home/Find.
- **Surfaces.** Bottom sheets (vaul) for actions and detail, Radix dialogs only for destructive confirms, full-screen routes for destinations. Sheets open/close with the existing `[data-state='open'|'closed']` keyframes; all motion gated on `prefers-reduced-motion`.
- **Motion.** Framer Motion 12. Springs for entrance (stiffness 260, damping 24), 180–240 ms fades for state changes, layout animations for list reorders. Never animate more than one hero element at once. Number changes use a count-up tween ≤600 ms.
- **Color.** Tailwind `primary` (sky) for actions, semantic greens/ambers/reds for states, neutral surfaces from `tokens.css`. Premium members keep gold accents where the shell already applies them; new surfaces must read correctly in Light, Dark, Classic, and Premium.
- **Type and density.** One headline per screen, one primary action per sheet, secondary actions as text buttons. Cards keep the `GameCard` rhythm: date tile left, title row, info rows, right rail.
- **Icons.** lucide-react only. No emoji as icons; emoji allowed in copy where playful.
- **Feedback.** `react-hot-toast` for transient confirmations, inline banners for persistent state, skeletons (`GameCardSkeleton` pattern) for loading, `EmptyStateCard` for empties with one clear next action.
- **Accessibility.** 44 px tap targets, 4.5:1 text contrast, roles/labels on every control, arrow-key support on segmented controls, RTL verified for `ar`, all copy in the 11 app locales.
- **Copy.** Plain, second person, verbs first ("Confirm seat", not "Seat confirmation"). No jargon from the schema in user-facing text.
