# PRD 355: PRD: Virtual goods shop UI

## Problem Statement

Coins circulate through admin grants, bets, and P2P transfers, and `Goods` plus `PURCHASE` transactions exist on the backend, but there is nothing to buy. `docs/product/not-shipped.md` lists the shop UI as absent. Without a sink, coins have no pull, and cosmetics (themes, app icons) have no storefront.

## Solution

A small in-app shop under the Wallet: a catalog of cosmetic goods purchasable with coins, with ownership recorded and effects applied by the client. First catalog: profile frames, chat bubble accents, an extra story sticker pack, and a name colour. Admin manages the catalog in the Admin panel.

## User Stories

1. As a player, I want a Shop entry in the Wallet, so that I can spend coins.
2. As a player, I want to see price, preview, and whether I already own an item.
3. As a player, I want a confirm step before purchase, so that mis-taps do not spend coins.
4. As a player, I want to equip or unequip owned cosmetics from Profile → Appearance.
5. As a player, I want purchases to appear in transaction history as PURCHASE with the item name.
6. As a player, I want a refund path when an admin withdraws an item, so that I am not short-changed.
7. As an admin, I want to create, price, hide, and feature goods, and upload preview art.
8. As a premium member, I want some items marked premium-only, so that membership has perks.
9. As a developer agent, I want ownership to be a table, not a JSON blob on User.
10. As a player, I want to preview a frame on my own avatar before buying, so that I know how it looks.
11. As a player, I want to gift an item to a friend, so that coins become social (uses the same purchase path with a recipient).

## UX / UI Design

### Entry
- Wallet modal header gains a **Shop** button with a small bag icon; the balance sits beside it. Also reachable from Profile → Appearance via "Get more styles".

### Shop screen
- Full-screen route `/shop` inside the shell. Top: balance pill (coins icon + number) pinned right; **Featured** carousel of large cards with the item rendered on the viewer's own avatar or a sample chat bubble; then category chips **Frames · Chat · Stickers · Name colours**; then a 2-column grid of item cards: live preview (frame around the viewer's avatar, bubble sample with the accent, sticker trio, name in the colour), name, price pill, and a state: **Buy**, **Owned**, **Equipped**, or a lock with "Premium" for premium-only.
- Tap opens the **item sheet**: a large preview that rotates through contexts (profile, roster row, chat) every 2 s with a crossfade; description; price; **Buy for 120 coins** primary; when owned, **Equip** / **Unequip**; overflow **Gift to a friend**.
- **Confirm**: a compact dialog "Buy Neon Frame for 120 coins? Balance after: 380" with **Confirm**. Success: the sheet's preview does a 500 ms shine sweep and the button morphs to **Equip**; toast "Added to your collection". Balance count-down animates.
- Insufficient coins: the buy button is disabled with "Need 40 more coins" and a helper linking to how coins are earned (bets, transfers, referrals).

### Appearance (Profile)
- New **Collection** section with the owned items as small tiles; tapping equips with a check; only one item per kind can be equipped. Frames render on the profile avatar immediately.

### Where equipped items show
- Frames: profile, player card, roster rows, chat avatars (small variant), leaderboard rows. Chat accent: the viewer's own outgoing bubbles only. Name colour: everywhere names render, except that premium gold wins when `showsPremiumStatus`. Sticker pack: appears in the sticker picker as an owned pack.

### Gift
- Gift sheet: friend picker (followers first) → confirm "Gift Neon Frame to Ana for 120 coins" → recipient gets a push "Ana sent you a gift 🎁" and the item appears in their Collection with a sparkle on first open.

### Admin
- Goods page in the Admin panel: table with kind, name, price, active, featured, premium-only, sales count; create/edit form with asset key and preview upload; withdraw action with a refund summary ("Refund 120 coins to 37 owners?").

### Empty, error
- Empty catalog: "The shop opens soon" with the mascot. Purchase failure: dialog stays open with an inline error and the balance re-fetched.

### Theme and motion
- Cards use the app surface tokens; premium items carry a thin gold border. Shine sweep and rotation previews are off under reduced motion.

### Accessibility
- Every preview has alt text; price pills read "120 coins"; state buttons have explicit labels; the rotation preview can be paused by tap.

## Implementation Decisions

- Extend `Goods`: `kind` enum (PROFILE_FRAME | CHAT_ACCENT | STICKER_PACK | NAME_COLOR), `assetKey`, `previewUrl`, `description`, `isActive`, `isFeatured`, `premiumOnly`, `sortOrder`, `stickerPackId?`. New `UserGoods` (userId, goodsId, purchasedAt, giftedByUserId?, equipped boolean) unique (userId, goodsId).
- Purchase: existing `PURCHASE` transaction path inside one DB transaction with the `UserGoods` insert; `TransactionRow.goodsId` already exists for history. Gift = purchase with `recipientUserId`; row belongs to the recipient, payer is the buyer.
- Equip: `PUT /users/me/goods/:id/equip` / `unequip` enforces one per kind; public user projection exposes `equippedGoods: { frame?, nameColor? }` so viewers render them. Chat accent is viewer-local (own bubbles).
- Sticker packs: ownership unlocks the pack in `UserStickerPrefs`.
- Admin: `PATCH /goods/:id`, `POST /goods/:id/withdraw` issuing `REFUND` transactions and clearing equipped state; Admin page in `Admin/` plain JS.
- Assets: frames and accents as CSS classes keyed by `assetKey` in `Frontend/src/styles/collection.css`; previews from S3.
- Feature flag `VITE_SHOP_ENABLED`; backend `SHOP_ENABLED`.
- Store compliance: coins remain non-purchasable with real money; document in `docs/product/not-shipped.md` update.

## Testing Decisions

- Service: purchase atomicity, double-purchase rejected, premium-only gate, gift ownership, withdraw refunds every owner once, one-per-kind equip.
- FE: catalog states, item sheet, confirm dialog math, Appearance collection, projection rendering of frames and name colour with premium precedence.
- Admin manual checklist.
- UI test plan: Wallet → Shop, Appearance → Collection, chat accent.

## Out of Scope

- Real-money top-up or IAP.
- Time-limited or consumable items.
- Trading between users.

## Further Notes

Confirm the shop is not intentionally hidden for store-review reasons before building; keep the catalog cosmetic and coin-only as specified.

## Design language (shared with every PRD in this set)

- **Mobile first.** Capacitor iOS/Android and mobile browsers are the primary target. Every overlay with an input lays out against the visual viewport via the keyboard contract (`Frontend/src/utils/keyboardLayout.ts`, `body.keyboard-visible`, `--overlay-bottom-inset`). Desktop gets the same components in the split layouts already used by Home/Find.
- **Surfaces.** Bottom sheets (vaul) for actions and detail, Radix dialogs only for destructive confirms, full-screen routes for destinations. Sheets open/close with the existing `[data-state='open'|'closed']` keyframes; all motion gated on `prefers-reduced-motion`.
- **Motion.** Framer Motion 12. Springs for entrance (stiffness 260, damping 24), 180–240 ms fades for state changes, layout animations for list reorders. Never animate more than one hero element at once. Number changes use a count-up tween ≤600 ms.
- **Color.** Tailwind `primary` (sky) for actions, semantic greens/ambers/reds for states, neutral surfaces from `tokens.css`. Premium members keep gold accents where the shell already applies them; new surfaces must read correctly in Light, Dark, Classic, and Premium.
- **Type and density.** One headline per screen, one primary action per sheet, secondary actions as text buttons. Cards keep the `GameCard` rhythm: date tile left, title row, info rows, right rail.
- **Icons.** lucide-react only. No emoji as icons; emoji allowed in copy where playful.
- **Feedback.** `react-hot-toast` for transient confirmations, inline banners for persistent state, skeletons (`GameCardSkeleton` pattern) for loading, `EmptyStateCard` for empties with one clear next action.
- **Accessibility.** 44 px tap targets, 4.5:1 text contrast, roles/labels on every control, arrow-key support on segmented controls, RTL verified for `ar`, all copy in the 11 app locales.
- **Copy.** Plain, second person, verbs first ("Confirm seat", not "Seat confirmation"). No jargon from the schema in user-facing text.
