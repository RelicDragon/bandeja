# PRD 352: PRD: Pair leaderboard (teams tab on Top)

## Problem Statement

Padel and doubles sports are played in pairs, and the app already models pairs (`UserTeam`, fixed `GameTeam` results), but rankings are strictly per user. There is no way to see the best pairs in a city, how a pair performs together, or who someone's strongest partner is beyond the private insights section.

## Solution

Add a **Pairs** mode to the leaderboard: ranked pairs per city and sport by win rate with a minimum-games floor, games together, and combined level. Tapping a pair opens the user-team page (or an ad-hoc pair sheet if the two never created a team) with shared history.

## User Stories

1. As a player, I want a Pairs toggle on Top next to Players, so that I can see the strongest duos.
2. As a player, I want pairs ranked by win rate with at least 5 games together, so that one lucky win does not top the table.
3. As a player, I want sort options: win rate, games together, combined level.
4. As a player, I want the same city/sport/period filters as the player leaderboard.
5. As a player, I want "scroll to my best pair" like scroll-to-me.
6. As a player, I want tapping a pair to show head-to-head history and a "Create team" button if we have not formalized it.
7. As a player, I want pairs to count only FINAL results where we were on the same side, so that the number means something.
8. As a player, I want my own pairs listed on Profile → Statistics, so that I can see partners ranked.
9. As a developer agent, I want pair stats materialized, not computed per request.
10. As a player, I want to see a "chemistry" indicator that compares the pair's win rate with each player's solo win rate, so that great partnerships stand out.
11. As a player, I want the top three pairs to feel like a podium, so that the tab is fun to open.

## UX / UI Design

### Top tab
- Under the existing filter header, the mode control becomes a `SegmentedSwitch` **Players · Pairs**. Switching cross-fades the list (200 ms) and keeps filters.
- **Podium header** (Pairs only): the top three pairs as three cards with heights 1st > 2nd > 3rd, each showing two overlapping avatars with a thin ring in gold/silver/bronze, names on two lines, win rate large, games small. Cards rise into place with a staggered 80 ms spring on first paint. Under reduced motion, no stagger.
- **Rows** below the podium: rank number, two avatars overlapping (24 px overlap), "Marko & Ana", second line "18 games · 72 %", right side a **chemistry** chip: a small bolt icon with "+9" when the pair's win rate beats the average of the two solo win rates by ≥5 points (green), neutral otherwise. Long-press shows the tooltip "Win rate together vs. on your own".
- **Sort** chips row: Win rate (default), Games, Level. Active chip in sky.
- **Scroll to my pair** floating pill appears when the viewer has any ranked pair below the fold; tapping scrolls and flashes the row.
- Rows of the viewer's own pairs get a soft sky left border.

### Pair sheet (no formal team)
- Bottom sheet 70%: header with the two avatars and names, stat tiles Games · Win rate · Chemistry, a **Recent together** list of up to 5 games as compact `GameCard`s with result chips, and a footer **Create a team** primary button (opens the existing team create flow with both members prefilled) plus **Invite to a game** secondary.
- If a `UserTeam` exists, tap goes straight to `/user-team/:id`, which gains the same stat tiles at the top.

### Profile → Statistics
- New **Your partners** section: horizontal cards per partner (avatar, name, games, win rate, chemistry chip), sorted by win rate with a floor of 3 games, "See all" opens a list sheet.

### Empty and loading
- No pairs qualify: `EmptyStateCard` "No pairs ranked yet. Play 5 games with the same partner to appear here." with a **Find a game** action.
- Loading: podium skeleton (three blocks) plus row skeletons.

### Accessibility
- Rows read "Rank 4, Marko and Ana, 18 games, 72 percent win rate, chemistry plus 9"; podium cards are buttons; sort chips are a radio group with arrow keys.

## Implementation Decisions

- Materialized `PairStat` (sport, cityId, userAId < userBId, games, wins, lastPlayedAt, combinedLevel, updatedAt) updated in the outcomes pipeline when a `GameOutcome` is written or reset; admin recalculation endpoint `POST /rankings/pairs/recalculate`.
- "Same side" source: `GameTeamPlayer` for fixed teams; for generated formats, per-`Match` team membership (`Team`/`TeamPlayer`) aggregated per game; a pair counts once per game when partners in the majority of that game's matches. Win = the pair's side won that game's outcome.
- Period windows reuse the ranking service; ≥5 games in period to rank. Chemistry = pairWinRate − mean(soloWinRate A, soloWinRate B) from `UserSportProfile` games/wins in the same period.
- API: `GET /rankings/pairs?cityId&sport&period&sort&cursor` with `me` context (mirrors `/rankings/user-context`); `GET /users/:id/partners?sport`.
- FE: `ProfileLeaderboard` mode switch, `PairPodium`, `PairRow`, `PairSheet` overlay `?pair=a,b` registered in `urlSchema`; `UserTeam` page stat tiles.
- Excludes EVENT, BAR, TRAINING, LEAGUE_SEASON; neutral technical league results excluded.

## Testing Decisions

- Pure aggregation tests for partner detection in fixed and generated formats, chemistry math.
- Pipeline test: outcome write and reset update `PairStat` symmetrically.
- Ranking API test: floor, sorts, period, me-context, cursor.
- FE: mode switch, podium order, sort chips, scroll-to-pair, pair sheet with and without team.
- UI test plan: Top tab Pairs rows, Profile partners.

## Out of Scope

- Pair ELO as a rated quantity.
- Pair invites from the leaderboard beyond the existing team flow.

## Design language (shared with every PRD in this set)

- **Mobile first.** Capacitor iOS/Android and mobile browsers are the primary target. Every overlay with an input lays out against the visual viewport via the keyboard contract (`Frontend/src/utils/keyboardLayout.ts`, `body.keyboard-visible`, `--overlay-bottom-inset`). Desktop gets the same components in the split layouts already used by Home/Find.
- **Surfaces.** Bottom sheets (vaul) for actions and detail, Radix dialogs only for destructive confirms, full-screen routes for destinations. Sheets open/close with the existing `[data-state='open'|'closed']` keyframes; all motion gated on `prefers-reduced-motion`.
- **Motion.** Framer Motion 12. Springs for entrance (stiffness 260, damping 24), 180–240 ms fades for state changes, layout animations for list reorders. Never animate more than one hero element at once. Number changes use a count-up tween ≤600 ms.
- **Color.** Tailwind `primary` (sky) for actions, semantic greens/ambers/reds for states, neutral surfaces from `tokens.css`. Premium members keep gold accents where the shell already applies them; new surfaces must read correctly in Light, Dark, Classic, and Premium.
- **Type and density.** One headline per screen, one primary action per sheet, secondary actions as text buttons. Cards keep the `GameCard` rhythm: date tile left, title row, info rows, right rail.
- **Icons.** lucide-react only. No emoji as icons; emoji allowed in copy where playful.
- **Feedback.** `react-hot-toast` for transient confirmations, inline banners for persistent state, skeletons (`GameCardSkeleton` pattern) for loading, `EmptyStateCard` for empties with one clear next action.
- **Accessibility.** 44 px tap targets, 4.5:1 text contrast, roles/labels on every control, arrow-key support on segmented controls, RTL verified for `ar`, all copy in the 11 app locales.
- **Copy.** Plain, second person, verbs first ("Confirm seat", not "Seat confirmation"). No jargon from the schema in user-facing text.
