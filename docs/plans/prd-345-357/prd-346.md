# PRD 346: PRD: Attendance confirmation and no-show tracking

## Problem Statement

Reminders go out 24h and 2h before a game, but there is no way to answer them. Organizers do not know until court time whether four people will actually show up. The app has no lightweight way for a player to say "yes, I'm coming" and no place where the organizer can see that at a glance.

## Solution

Turn the reminder into a question, and keep the answer **purely informative**. PLAYING participants can confirm attendance from the push shade, Telegram button, or game details. Organizers see a confirmation strip, can nudge unconfirmed players, and can note a no-show afterwards. Nothing is enforced: unconfirmed players never lose their seat, no deadline exists, and no rating or reliability value changes. The attendance record shows up as a friendly "Shows up" stat on the player card once there is enough data.

## Product principle

Confirmation is a courtesy signal, not a contract. The system never removes, demotes, penalizes, or auto-fills based on it. The only outputs are visibility (dots, counts, a stat) and communication (nudges, system messages).

## User Stories

1. As a participant, I want the 24h reminder to offer "I'm coming" and "Not sure yet", so that I answer without opening the app.
2. As a participant, I want the same actions in game details, so that I can change my answer later.
3. As a participant, I want confirming to be possible any time after joining, not only after the reminder, so that eager players can confirm early.
4. As a participant who cannot make it, I want a clear path to free my seat, but only through the normal leave flow with confirmation, never from a push action.
5. As an organizer, I want the roster to show confirmed / not yet / not sure per player, so that I know where I stand.
6. As an organizer, I want a one-tap "Nudge" that sends one push and one chat system message to unconfirmed players, rate limited, so that I do not spam.
7. As an organizer, I want the confirmation count visible on my Home cards, so that I do not need to open each game.
8. As an organizer or admin, I want to note a player as a no-show after the game, with undo, so that I remember and the player is informed.
9. As a noted player, I want a friendly notification with a way to reply in chat, so that mistakes are cleared up.
10. As any player, I want a "Shows up" percentage on my player card after enough games, so that reputation is visible without being punitive.
11. As a player, I want no attendance state to ever change my level, reliability, seat, or queue position, so that confirmation stays low-stakes.
12. As a Telegram user, I want inline confirm buttons on the reminder message.
13. As a Watch user, I want a Confirm button on the Next Game view when the game is within 24 h.
14. As a developer agent, I want attendance state on the participant row, so that queries are simple.

## UX / UI Design

### The confirmation moment
- **Push (24 h)**: "Tomorrow 19:00 · Padel Centar · court 3. Are you coming?" with actions **I'm coming** and **Not sure yet**. Both are one-tap shade actions; neither opens the app. **I'm coming** shows the system confirmation "Seat confirmed 👍"; **Not sure yet** shows "Noted. You can confirm later."
- **Push (2 h)** only to players who have not answered: "Starts in 2 h at Padel Centar. Coming?" same actions. Never a third message.
- **Telegram**: same two inline buttons under the reminder; tapping edits the message to "✅ You're confirmed" or "🤔 Noted, not sure yet".

### Game details
- **Attendance card** under the header for PLAYING participants **except the owner** when `timeIsSet` and status ANNOUNCED. (Amended after ship: organizing *is* the answer, so the owner is never asked and counts as confirmed — `docs/domains/games.md` "The organizer's implicit yes".) Two buttons side by side: **I'm coming** (primary sky) and **Not sure yet** (outline). After answering, the card compresses to one row: green "You're confirmed · Tue 19:00" or amber "You're not sure yet", each with a **Change** text button. 220 ms height/opacity transition.
- A subtle caption under the card: "Just so the organizer knows. Your seat is yours either way." This line is the product principle made visible.
- **Can't make it at all?** is a small text link under the card that opens the existing leave-game confirmation. Nothing about attendance ever removes a player.
- **Roster**: each PLAYING row gets a status dot on the avatar's lower right: green check (confirmed), grey ring (no answer), amber question (not sure). After the game, an optional grey "No-show" tag can appear (organizer note). Legend on long-press and as a caption for organizers.
- **Organizer strip** above the roster: "2 of 4 confirmed" progress pill that fills live via socket (300 ms width spring). Right side: **Nudge** button with a cooldown caption "Nudge again in 5 h". There are no settings, deadlines, or release options.

### Home and Find cards
- For the viewer's own games, the `GameCardRightRail` shows a mini avatar stack with status dots and a fraction "3/4". Purely visual; no border color changes, no urgency treatment.

### No-show note (after the game)
- Roster overflow (owner/admin) after FINISHED/ARCHIVED or FINAL: **Note as no-show**. Dialog: "Note Ana as a no-show? They'll get a friendly heads-up and can reply in chat. You can undo any time within 7 days." Neutral primary button, not red.
- After noting: grey tag on the row, toast "Noted · Undo", and a neutral chat system message "Organizer noted Ana as a no-show".
- Player notification: "You were noted as a no-show for Tue 19:00 at Padel Centar. If that's wrong, reply in the game chat." Deep-links into the chat.

### Player card and Profile
- **Player card**: a **Shows up** tile with a percentage and a small ring gauge in a single sky tone (no red/amber grading). Hidden until 5 recorded games. Tooltip: "Games confirmed and attended in the last 12 months."
- **Profile → Statistics**: the same tile plus a 12-month sparkline; own no-show notes listed with links to the chat (own profile only).

### States and edge cases
- Game without `timeIsSet`: no attendance UI.
- Organizer row shows "You (organizer)" in the no-show list. (Amended after ship: their roster dot is always the green confirmed one — they are never asked, so there is no "unless they answer".)
- Substitution: the substitute starts with no answer and receives the 2 h push if inside the window.
- League fixtures: same UI; no-show note by season owner/admin.
- Offline: answers queue with a pending outline and sync on reconnect.
- Reduced motion: progress pill jumps without spring.

### Accessibility
- Status dots pair with visually hidden text; buttons have explicit labels; the ring gauge exposes the percentage as text.

## Implementation Decisions

- Schema: `GameParticipant.attendance` enum `UNANSWERED | CONFIRMED | UNSURE` default `UNANSWERED`, `attendanceUpdatedAt`; `GameParticipant.noShowNotedById`, `noShowNotedAt`. `UserSportProfile.attendedCount`, `noShowCount` (informational counters only).
- API: `POST /games/:id/attendance` `{ state: CONFIRMED|UNSURE }` (participant), `POST /games/:id/participants/:userId/no-show` and `DELETE` for undo (owner/admin, `canEditGame`, within 7 days), `POST /games/:id/attendance/nudge` (owner/admin, one per 6 h per game).
- Reminder push (`game-reminder-push.notification.ts`) gains two actions via `pushInviteActionToken.service.ts` (new kinds `ATTENDANCE_CONFIRM` / `ATTENDANCE_UNSURE`). Android shade actions via the existing invite-action path, iOS notification category with two actions, Telegram callback prefix `at:`.
- No scheduler behavior beyond the existing 24 h / 2 h reminders (the 2 h reminder is filtered to unanswered players). No auto-release, no deadline, no seat changes.
- Attendance counters: `attendedCount` increments when a CONFIRMED participant's game reaches FINAL/FINISHED without a no-show note; `noShowCount` on note, decrement on undo. Nothing writes to `level`, `reliability`, or `ratingUncertainty`. No `LevelChangeEvent`.
- Attendance % = attended / (attended + noShow) over 12 months; in the public user projection only when the denominator ≥5.
- Nudge: `GAME_REMINDER` type to unanswered players plus a system message via `createSystemMessageWithNotification`.
- Prefs: prompts and nudges under `sendReminders`; no-show note under `sendMessages`.
- Socket: `game:attendance-updated` on `game-{id}`.
- Watch: Next Game view shows a Confirm button when the envelope carries `attendance: 'UNANSWERED'` and the game is within 24 h (extend the next-games envelope).

## Testing Decisions

- Service tests: action token round-trip; attendance never mutates `status`, seat, or queue; no-show window and undo; counters and % threshold; no rating fields touched (assert unchanged).
- FE: attendance card states and caption, roster dots, organizer strip live update, nudge cooldown, no-show toast undo, player card tile threshold.
- Telegram callback parser test for `at:`.
- UI test plan rows: reminder actions (manual on device), details confirm, no-show note, player card tile.

## Out of Scope

- Any enforcement: auto-release, deadlines, penalties, reliability or level effects.
- Financial consequences.
- Automatic no-show detection from live scoring or geolocation.
- Attendance for EVENT RSVPs.

## Further Notes

Product decision: confirmation is informative only. If enforcement is ever wanted, it must be a separate PRD with its own opt-in.

## Design language (shared with every PRD in this set)

- **Mobile first.** Capacitor iOS/Android and mobile browsers are the primary target. Every overlay with an input lays out against the visual viewport via the keyboard contract (`Frontend/src/utils/keyboardLayout.ts`, `body.keyboard-visible`, `--overlay-bottom-inset`). Desktop gets the same components in the split layouts already used by Home/Find.
- **Surfaces.** Bottom sheets (vaul) for actions and detail, Radix dialogs only for destructive confirms, full-screen routes for destinations. Sheets open/close with the existing `[data-state='open'|'closed']` keyframes; all motion gated on `prefers-reduced-motion`.
- **Motion.** Framer Motion 12. Springs for entrance (stiffness 260, damping 24), 180–240 ms fades for state changes, layout animations for list reorders. Never animate more than one hero element at once. Number changes use a count-up tween ≤600 ms.
- **Color.** Tailwind `primary` (sky) for actions, semantic greens/ambers/reds for states, neutral surfaces from `tokens.css`. Premium members keep gold accents where the shell already applies them; new surfaces must read correctly in Light, Dark, Classic, and Premium.
- **Type and density.** One headline per screen, one primary action per sheet, secondary actions as text buttons. Cards keep the `GameCard` rhythm: date tile left, title row, info rows, right rail.
- **Icons.** lucide-react only. No emoji as icons; emoji allowed in copy where playful.
- **Feedback.** `react-hot-toast` for transient confirmations, inline banners for persistent state, skeletons (`GameCardSkeleton` pattern) for loading, `EmptyStateCard` for empties with one clear next action.
- **Accessibility.** 44 px tap targets, 4.5:1 text contrast, roles/labels on every control, arrow-key support on segmented controls, RTL verified for `ar`, all copy in the 11 app locales.
- **Copy.** Plain, second person, verbs first ("Confirm seat", not "Seat confirmation"). No jargon from the schema in user-facing text.
