`costSharePermissions.ts` were judged correct and extended, `gameCost.types.ts` is used

## 2. Contract deltas and deliberate deviations

1. **`SendMoneyToUserModal` is not used for the coin branch.** The PRD says the coin option
   "prefills the existing `SendMoneyToUserModal`". Doing that would transfer the coins in the
   modal and then transfer them *again* server-side when the share is marked settled — or force
   a two-step client flow where a crash between the steps loses the money. Instead
   `POST /cost-shares/me/paid { method: 'COINS' }` calls the **same**
   `TransactionService.createTransaction({ type: TRANSFER, … })` the modal calls, and writes the
   timestamps only after it returns. Same code path, same ledger row, one round trip, no
   double-spend window. The modal is untouched.
2. **Freeze is lazy, not hooked into `outcomes.service.ts`.** `Game.costFrozenAt` is set the
   first time the ledger is synced while `resultsStatus === 'FINAL'` — which happens on the next
   card read *or* on the hourly scheduler's freeze pass, whichever comes first. This avoids
   editing a 900-line shared transaction in `results/outcomes.service.ts`. **If you want the
   freeze stamp to be exact**, add this one line inside the `previousResultsStatus !== 'FINAL'`
   branch there, after `tx.game.update`:
   ```ts
   // PRD 348 — freeze the cost split at the moment results go final.
   await tx.game.update({ where: { id: gameId }, data: { costFrozenAt: new Date() } });
   ```
   Everything still works without it; the 24 h reminder is then accurate to within an hour.
3. **No i18next plural suffixes in `cost.json`.** `localeParity.test.ts` asserts an *exact* key
   set across all 11 locales, which is incompatible with Russian/Czech/Serbian/Arabic needing
   `_few`/`_many` alongside `_one`/`_other`. Rather than add an allowlist exception or ship
   grammatically wrong Russian, every count-bearing string is phrased so number agreement is
   safe in all 11 languages (`{{players}}`, `{{coins}}`, `{{hours}}` — never i18next's magic
   `count`). If the parity test is later taught about plural suffixes, these six keys are the
   ones to revisit: `cost.sheet.coins`, `cost.card.totalFor`, `cost.create.preview`,
   `cost.toast.settledCoins`, `cost.toast.reminded`, `cost.remindCooldown`.
4. **Backend reminder copy lives in `costReminderCopy.ts`, not `utils/translations.ts`.** That
   file is a single 3.6k-line map every concurrent branch is editing; two strings with no other
   consumer did not justify 22 merge-conflict-prone insertions. `t()` fallback semantics are
   reproduced (unknown language → English).
5. **`PER_TEAM` games show no cost card.** A team price only yields a game total when the team
   count is known, and nothing on `Game` states it. `COST_SPLIT_PRICE_TYPES` is therefore
   `['TOTAL', 'PER_PERSON']`. Documented in the domain delta.
6. **`GameCostShare` has no `remindedAt` column** and `GameLogType` only has `USER_INVITED`, so
   there was no schema-backed place to persist the reminder dedupe. Hence the Redis-first /
   `PlatformSetting`-fallback claim (§1). If a later wave adds `GameCostShare.remindedAt` or a
   `CostReminderDelivery` table, `costReminderDedupe.ts` is the only file that changes.
7. **"Owner `NON_PLAYING` is excluded unless payer" implemented literally.** A non-playing
   organizer who is the payer *does* get a share row and is counted in the divisor. This is
   what the PRD says; note that it means the organizer absorbs a share of a game they did not
   play. Flag it if the intent was the opposite.

## 4. Known gaps

- **No `*.integration.test.ts` for the service layer.** The share maths, the permission matrix,
  the coin-settle guard rails and the reminder dedupe are all covered as pure functions, and
  `planCoinSettlement` / `selectSplitParticipantIds` / `deriveShareState` were extracted
  specifically so the risky logic is exercised without a database. What is *not* covered by an
  automated test is the Prisma plumbing itself: the create/update/delete diff inside
  `syncGameCostShares`, the substitution row move, and the freeze write. Those are covered by
  UI-test-plan rows GD-CS-23/24/25/26 instead.
- **No "count-up" animation on the outstanding amount.** The design language mentions count-up
  for number changes; the summary strip renders the amount directly. `CountUpNumber` exists and
  could be dropped in.
- **The reminder push opens the game, not the settle sheet.** `NotificationData` has no free-form
  deep-link field, so the payload carries `gameId` only. The in-app deep links
  (`?section=cost&settle=1`) work and are used by the Wallet's **Settle** button; wiring them into
  the push tap would need a new `NotificationData` field, which belongs to whoever owns that type.
- **Nothing was verified by running anything.** No `tsc`, no vitest, no lint, per the hard rules.
  Types were checked by reading; several casts through `unknown` were used where a Prisma
  `select` result meets a hand-written row type.
