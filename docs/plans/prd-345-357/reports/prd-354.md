### i18n

`clubPage.json` filled in all 11 locales with real translations. Three plural families
(`rating.summary`, `today.freeHours`, `info.cancellationNotice`) carry the CLDR categories each
locale needs: `_one/_other` for en/es/hi, `+_few/_many` for ru, `+_few` for sr/cs,
`_zero/_one/_two/_few/_many/_other` for ar, `_other` alone for zh/ja/th/id. Verified mechanically
against every rule `localeParity.test.ts` enforces (family key set, `_other` present everywhere,
identical placeholders per form, no value byte-identical to English) — all pass. Ratings, review
counts and "updated N minutes ago" go through `Intl.NumberFormat` / `Intl.RelativeTimeFormat` with
the active locale. No `PARITY_IDENTICAL_ALLOWLIST` entry was needed.

Court **surface** text is rendered from the operator's own free-form value (de-shouted) rather than
translated — there is no fixed vocabulary in the schema to translate against.

## 2. Security notes (the point of this PRD)

- `/clubs/:id/public` is a **whitelist** Prisma `select`. `integrationType` / `integrationConfig`
  are read only to derive `booking`, and are destructured away in `projectPublicClub` before the
  row is serialised. `findPublicClubContractIssues()` is a second belt, asserted in the test.
- The guest test serialises the payload through `JSON.parse(JSON.stringify(...))` before asserting,
  so a getter or non-enumerable property could not slip past an `in` check, and it asserts the
  literal secret string does not appear anywhere in the JSON.
- The test also proves the guardrail **catches** a regression (re-added `integrationConfig`, a
  court's `externalCourtId`, an extra key on `booking`), not just that it passes vacuously.
- `isFavorite` / `isAdmin` are always booleans, never `undefined`, so the UI has no third state.
  `isAdmin` only shows the Manage button; `/my-clubs` remains protected server-side.
- Regulars: public profiles only, blocks honoured in both directions, per-viewer filtering happens
  **after** the shared cache, and the payload carries no play counts and no game ids.
- The today endpoint returns hour buckets and one timestamp. No provider id, no venue id, no
  Supabase URL ever reaches the browser. NSPADELSUPABASE is not in the `queryExternalBlocks` merge,
  so an NSPadel strip is games + holds only — that is honest, not a bug.

## 3. Contract deltas

1. **A guest-readable games endpoint was needed.** CONTRACT/PRD say "upcoming games via
   `useAvailableUpcomingGames` with `clubIds=[id]`", but `/games/available/upcoming` is
   `authenticate`-only and `GameReadService.getAvailableUpcomingGames` throws 401 on a missing user
   id, while the PRD's user story 2 requires a guest to see the club's public games. I added
   `GET /clubs/:id/public-games` which calls the **same** `fetchAvailableGamesPage` and the **same**
   card projection — no new query, one FE code path for guest and member.
2. **The Find query is city-scoped to the *viewer*.** `buildAvailableWhere` sets
   `where.cityId = resolveCityId(viewer)`. On a club page that is wrong, so the club's `cityId` is
   passed explicitly as `userCityId`. Worth knowing if anyone else reuses that helper off the Find
   tab.
3. **`useFindFromUrl` was dead code.** It existed but nothing imported it, and Find's filters come
   from `useGameFilters` / `gameFiltersStorage`. I extended it with `clubIds` *and* wired it into
   `FindTab` through a pure `applyFindClubIdsFromUrl` rule, which is the part that was missing.
4. **"Book → connect sheet" could not be implemented as written.** `ConnectClubSheet` needs the
   club's `integrationConfig`, which is exactly what this page must never receive. **Book** instead
   hands the player to create-game, which loads the full club for an authenticated user and already
   owns both halves (connected → provider slots, not connected → connect sheet). Documented in the
   domain delta with a "do not "improve" this" note.
5. **`ClubDetailPanel` is reused, not mounted.** It takes a full `Club` (including
   `integrationConfig`) and drives booking-auth hooks and snapshot refreshes, so mounting it on a
   guest page is not possible without breaking rule 4. The Info section reuses its exported
   `amenityEntries` and the same helpers it uses (`ClubMiniMap`, `getClubMapsSearchUrl`,
   `websiteDisplayHost`, `getTelUrl`, `openExternalUrl`, `useTranslatedGeo`).
   `ClubReviewsSection` **is** mounted as-is.
6. **`MainPage.scrollablePage` had to learn about `club`.** Wave 2 routed the page but left it in
   the non-scrolling branch (`min-h-0 overflow-hidden`), which would have clipped it entirely. One
   line added, with a comment.
7. **There is no profile-visibility column on `User`.** "Public profiles only" is implemented as
   `isActive: true, nameIsSet: true`. If a real visibility flag is ever added it belongs in that
   one `where`.

## 6. Known gaps

1. **Book does not open the connect sheet directly** — see contract delta 4. It routes to
   create-game, which owns both paths. This is a deliberate security trade, not an oversight.
2. **`ClubDetailPanel` is not mounted on the page** — see contract delta 5. The Info section is
   composed from its exported helper and the same primitives, and `ClubReviewsSection` is mounted
   verbatim as the PRD requires.
3. **Opening hours are one line, not a weekday table.** The schema has only flat
   `openingTime` / `closingTime` strings. The PRD's "today highlighted" is therefore rendered as
   "Open 08:00 – 23:00 / same hours every day" rather than an invented schedule. Calling this out
   explicitly because it reads like a missing feature and is not.
4. **`FiltersPanel` prunes club ids that are not in the current city's catalogue**
   (`pruneFindFilterClubIds`). A `/find?clubIds=` link to a club in a *different* city than the
   one Find is browsing will be applied and then pruned. Out of scope to change here, but a real
   edge for cross-city shares — worth a follow-up.
5. **The court chevron in Find's advanced filters is 32 px, not 44 px.** The chip row is a dense
   wrap layout and a 44 px control would break it. The chip itself remains the primary target and
   the chevron is secondary. Flagging rather than hiding it.
6. **`ClubRegularsRow` shows faces without a level ring** — the regulars projection deliberately
   carries no rating, so rendering it through `PlayerAvatar` would imply data it does not have.
   Tapping a face opens the full player card, which fetches the real profile.
7. **The "player card Home court chip"** entry point listed in the PRD's Entry points belongs to
   the recap PRD (353) and was not added here.
