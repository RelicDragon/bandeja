#### 1.1 Security fix — the live hole is closed

`POST` / `PUT` / `DELETE` on `/api/goods` carried **`authenticate` only**: any signed-in player
could create, reprice or delete catalogue items. The unfiltered `GET` also leaked inactive /
unreleased items. Every route on that router — reads included — is now behind `requireAdmin`, and
`Backend/src/routes/goodsAdminGuard.integration.test.ts` asserts **403 for a valid non-admin token
and 401 anonymous on every one of them**, then checks that no row was actually mutated.

Player-facing reads moved to `/api/shop`; nothing on `/api/goods` is for players any more.

#### 1.2 Load-bearing invariants (please add to `docs/product/constraints.md`)

1. **Purchase atomicity.** `Backend/src/services/shop/shopPurchase.service.ts` — the wallet debit,
   the `PURCHASE` transaction and the `UserGoods` insert are one `prisma.$transaction`. The
   `UserGoods` unique index is the idempotency key; the code uses `create`, **not** `upsert`, so a
   lost double-tap race surfaces as `P2002` → 409 instead of silently succeeding twice. Do not
   "simplify" this into `TransactionService.createTransaction` (it opens its own transaction).
2. **Server-side premium gate.** `rejectPurchase` in `Backend/src/services/shop/shopRules.ts` is the
   only gate. The UI lock is cosmetic.
3. **Refund idempotency.** `refundGoodsOwners` skips an owner who already holds a `REFUND` row for
   that `goodsId`; re-running a withdrawal must never pay anybody twice.
4. **Coins are not purchasable with real money.** Store-compliance constraint, not a preference.
5. **Premium gold beats a bought name colour** whenever `showsPremiumStatus(user)` —
   `resolveNameClass` in `Frontend/src/features/collection/collectionAssets.ts`.

### i18n

`shop.json` filled in all 11 locales (`en, ru, sr, es, cs, ar, zh, id, hi, th, ja`), ~70 keys.
`index.ts` files untouched. Verified locally against every rule `localeParity.test.ts` enforces:
same family key set, `_other` present for every family in every locale, identical placeholders on
**every plural form**, and no non-`en` value byte-identical to English.

Plural families: `coins`, `needMoreCoins`, `refundOwners` — `_one/_other` (en, es, hi),
`+_few/_many` (ru), `+_few` (sr, cs), `_zero/_one/_two/_few/_many/_other` (ar), `_other` alone
(zh, ja, th, id). Prices, balances and shortfalls all render through one `coinsPhrase()` helper, so
every coin amount in the UI is both `Intl`-grouped per locale and correctly pluralized.

## 4. Known gaps

1. **Nothing is seeded.** The catalogue is empty until an admin creates items in Admin → Goods with
   asset keys that match `collection.css` (`frame-neon`, `frame-gold`, `frame-aurora`,
   `frame-court`, `frame-sunset`, `frame-mono`, `name-coral`, `name-mint`, `name-violet`,
   `name-ocean`, `name-amber`, `accent-neon`, `accent-sunset`, `accent-mint`, `accent-violet`).
   Until then `/shop` correctly shows "The shop opens soon". No seed script was written.
2. **Frames reach avatars through `PlayerAvatar`.** Surfaces that render an avatar without it
   (`MentionSuggestionAvatar`, `pairs/PairAvatars`, `clubPage/ClubRegularsRow` use
   `PlayerAvatarFace` directly) show no frame. Worth a follow-up if the critic wants full coverage.
3. **Another player's cosmetics refresh on navigation, not live.** The batch store caches for the
   session; there is no socket event when somebody re-equips.
4. **No FE test for `ShopItemSheet` itself.** Its logic is covered indirectly (`shopFormat.test.ts`
   for the button/label/error mapping, `ShopItemCard.test.tsx` for states), but the sheet's
   rendering — vaul + Radix + two nested overlays — is not mounted in jsdom.
5. **`previewRosterHint` is a fixed sample string** ("Saturday at 18:00"), not a real fixture.
6. **No heavy command was run** (per the brief): no `tsc`, no vitest, no eslint, no Prisma. Import
   paths were verified by script; types were not machine-checked.
