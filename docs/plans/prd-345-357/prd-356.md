# PRD 356: PRD: Telegram bot /play and /live commands

## Problem Statement

The bot handles auth, `/my`, and `/games`, and mirrors notifications with inline buttons. Two high-value actions still require the app: signalling "I want to play" and finding a live match to watch. Telegram-first users in group chats cannot do either.

## Solution

Add `/play` to create or cancel a play intent from Telegram with day and time-of-day buttons, and `/live` to list in-progress public games in the user's home city with broadcast links. Both reuse existing services; the bot only adds command parsing and inline keyboards.

## User Stories

1. As a linked Telegram user, I want `/play` to ask today / tomorrow / day after, then anytime / morning / afternoon / evening, so that I post an intent in two taps.
2. As a user with an OPEN intent, I want `/play` to show it with a Cancel button instead of creating a duplicate.
3. As a user, I want play-intent match and game-fit notifications to keep arriving in Telegram with the existing buttons.
4. As a user, I want `/live` to list live public games in my home city with score and a "Watch" link.
5. As a group chat member, I want `/live` to work in groups like `/games`, so that club groups can share what is on court.
6. As a user without a linked account, I want `/play` to send me the login link flow.
7. As an operator, I want both commands rate limited per chat.
8. As a developer agent, I want commands implemented as files in `services/telegram/commands/`, following the existing pattern.
9. As a user, I want the bot menu (the "/" button) to list the new commands with descriptions in my language.
10. As a group member, I want `/play` in a group to post a lightweight "Marko is looking to play tomorrow evening" with a Join-me button that opens the app's Looking tab, so that groups become a lobby.

## UX / UI Design

### Command menu
- Register `play` and `live` with the bot API command list, localized descriptions: "Say you want to play", "Games happening right now".

### `/play` conversation (private)
1. Bot replies with a card-like message: "When do you want to play? 🎾" and a 3-button row **Today · Tomorrow · {Weekday}** (third label is the actual day name).
2. After a day: the message edits in place to "Tomorrow · what time?" with a 2×2 keyboard **Anytime · Morning · Afternoon · Evening** and a **← Back** button.
3. After time: message edits to a confirmation block:
   "✅ You're looking to play
   🎾 Padel · Belgrade
   📅 Tomorrow, evening
   We'll message you when players or a game match."
   with buttons **Open in app** (deep link to the court lobby) and **Cancel**.
- Existing OPEN intent: `/play` replies with the same confirmation block and a **Stop looking** button; tapping edits the message to "Stopped looking" with a **Look again** button.
- Not linked: reply with the standard login-link message from `loginMessage.service.ts`.
- Errors (no home city or no primary sport): "Set your city in the app first" with an **Open profile** deep link.

### `/play` in groups
- Posts "🎾 Marko is looking to play tomorrow evening in Belgrade" with **I'm in too** (creates an intent for the tapper via the same flow, private confirmation) and **Open app**. Rate limited to one post per user per 6 h per group.

### `/live`
- Reply: header "🔴 Live now in Belgrade" then up to 5 blocks:
  "Padel Centar · court 3
  Marko / Ana  **6-4 3-2**  Luka / Ivan
  Started 23 min ago"
  each followed by a **Watch** URL button to the broadcast page. Footer "Updated just now · /live to refresh". Empty: "Nothing live right now. /games shows what's coming up."
- Scores use monospace via Telegram Markdown for alignment; names truncated at 12 chars.

### Accessibility and localization
- All strings via the bot's existing locale resolution; emoji kept minimal and consistent with existing bot messages.

## Implementation Decisions

- `/play`: `play.command.ts` + callback prefix `pi:` (`pi:d:<offset>`, `pi:t:<slot>`, `pi:cancel`, `pi:again`, `pi:join:<intentId>`) in `handlers/callback.handler.ts`. Uses the play-intent create/cancel service with primary sport, home city, `dateKeys` from the chosen day in city timezone, `timeOfDays` from the choice. Enforces one OPEN intent per city/sport by showing the existing intent.
- Group `/play`: `requireChat` semantics from `/games`; the post stores the poster's intent id for **I'm in too**.
- `/live`: `live.command.ts` reads the live-only available-games query from the Live now PRD (`resultsStatus = IN_PROGRESS`, `isPublic`, `showOnLiveRail`) for the user's home city or the group's configured city; scores from `liveSummary`; Watch links minted with the public broadcast token.
- Command registration via `setMyCommands` per supported language at bot startup.
- Rate limit through `middleware.ts` at 10/min per chat; group `/play` post limit stored in Redis.
- Deep links use the existing `/login/:telegramKey` auto-login when the user is not signed in on the device.

## Testing Decisions

- Command handler tests with mocked grammy context (existing `*.command` test style) for private, group, unlinked, and error branches.
- Callback parsing tests for `pi:` variants and message edits.
- Service integration: intent created with expected `dateKeys`/`timeOfDays`; `/live` output format snapshot.

## Out of Scope

- Club or level preferences from Telegram (app only).
- Live score streaming edits in Telegram.

## Design language (shared with every PRD in this set)

- **Mobile first.** Capacitor iOS/Android and mobile browsers are the primary target. Every overlay with an input lays out against the visual viewport via the keyboard contract (`Frontend/src/utils/keyboardLayout.ts`, `body.keyboard-visible`, `--overlay-bottom-inset`). Desktop gets the same components in the split layouts already used by Home/Find.
- **Surfaces.** Bottom sheets (vaul) for actions and detail, Radix dialogs only for destructive confirms, full-screen routes for destinations. Sheets open/close with the existing `[data-state='open'|'closed']` keyframes; all motion gated on `prefers-reduced-motion`.
- **Motion.** Framer Motion 12. Springs for entrance (stiffness 260, damping 24), 180–240 ms fades for state changes, layout animations for list reorders. Never animate more than one hero element at once. Number changes use a count-up tween ≤600 ms.
- **Color.** Tailwind `primary` (sky) for actions, semantic greens/ambers/reds for states, neutral surfaces from `tokens.css`. Premium members keep gold accents where the shell already applies them; new surfaces must read correctly in Light, Dark, Classic, and Premium.
- **Type and density.** One headline per screen, one primary action per sheet, secondary actions as text buttons. Cards keep the `GameCard` rhythm: date tile left, title row, info rows, right rail.
- **Icons.** lucide-react only. No emoji as icons; emoji allowed in copy where playful.
- **Feedback.** `react-hot-toast` for transient confirmations, inline banners for persistent state, skeletons (`GameCardSkeleton` pattern) for loading, `EmptyStateCard` for empties with one clear next action.
- **Accessibility.** 44 px tap targets, 4.5:1 text contrast, roles/labels on every control, arrow-key support on segmented controls, RTL verified for `ar`, all copy in the 11 app locales.
- **Copy.** Plain, second person, verbs first ("Confirm seat", not "Seat confirmation"). No jargon from the schema in user-facing text.
