# PRD 359: PRD: Seat count and queue position on game cards

## Problem Statement

A Find or My card tells you whether a game has room ("Add me to game") or not ("Join the queue"), and nothing more. Two facts that decide whether someone taps are missing: how many seats are actually left, and, for a player already queued, where they stand. The game page has both (PRD 347 added `GameQueuePanel` with `spots.queue.position`), but the card, which is where most decisions happen, does not.

## Solution

Put the two numbers into controls that already exist on the card. The join button label gains a seat count when seats are scarce; the viewer's own participation badge shows the queue position when they are queued. No new row, no new tag, no new colour. Both values are computed on the client from participants already present in the card payload.

## User Stories

1. As a browsing player, I want "1 seat left" on the join button when a game is nearly full, so that I act now instead of later.
2. As a browsing player, I want the full game's button to say how many people are already waiting, so that I know whether queueing is worth it.
3. As a queued player, I want my card badge to show "In queue · 2nd", so that I do not open the game to check.
4. As a player in a mixed-pairs game, I want the count to reflect seats open for my gender, or no count at all, never a misleading one.
5. As an organizer, I want nothing to change on my own game's card except the same honest numbers.
6. As a developer agent, I want seat and position computations in one pure module shared by Find, My and chat game cards.

## UX / UI Design

### Join button (`GameCardJoinButton`)
- Current labels stay the default: **Add me to game** / **Join the queue**.
- When open seats ≤ 2 (and > 0): **Add me · 1 seat left** / **Add me · 2 seats left**. Above 2, unchanged. Never "0 seats left".
- When full and the queue is non-empty: **Join the queue · 2 waiting**. Empty queue: unchanged.
- Label stays on one line; on the narrowest cards the suffix collapses to **· 1 left** / **· 2 waiting** (existing `hidden sm:inline` pattern for the long form).
- No urgency colour, no pulsing. The existing spot-opened treatment (PRD 347 `spotJustOpened`) is untouched and takes precedence for its window.

### Participation badge (`GameCardHeaderTags`, `getGameCardMyParticipationBadge`)
- `in_queue` badge text becomes **In queue · 2nd** (ordinal localised). When position is unknown (participants truncated), the badge stays **In queue**.
- Badge size and position unchanged.

### Gender-aware seats
- `genderTeams === 'MIX_PAIRS'`: compute seats open for the viewer's gender using the existing client "gender MIX precision" residual helper. If the viewer's gender is unset, show no count (button label unchanged).
- `MEN` / `WOMEN` games: count is total open seats; the existing gender gate on join still applies.

### Entity types
- Counts only where `entityCapabilities.unboundedRoster === false` and the entity has seats (GAME, TOURNAMENT, TRAINING, BAR, LEAGUE fixtures with a roster). EVENT never shows counts.

### Accessibility and locales
- Button `aria-label` carries the full sentence ("Add me to game, one seat left"). Ordinals via `Intl.PluralRules(locale, { type: 'ordinal' })` with a per-locale suffix table; locales without ordinal suffixes (ru, sr, zh, ja, th, ar, hi, id) use the "No. 2" form from their resource file. All copy in 11 locales, RTL checked.

## Implementation Decisions

- New pure module `Frontend/src/components/gameCard/gameCardSeatInfo.ts`: `computeSeatInfo(game, participants, viewer) → { openSeats: number | null, queueLength: number, viewerQueuePosition: number | null }`. Reuses `readQueueState` from `Frontend/src/features/spot-opened/queueState.ts` for the position (same ordering as the game page: `IN_QUEUE` by `joinedAt` ascending) and the existing participation helper for `isFull`.
- Projection check: the Find card select (`FIND_CARD_GAME_SELECT` participants include, `availableGamesCard.projection.ts` ~line 246/260) must carry `status`, `joinedAt`, `role` and `user.gender` for every participant, not only PLAYING. Verify; add `joinedAt` if absent (select-only change, no migration). Same for the My tab select in `myTabData.service.ts` and the chat game card payload. If any payload truncates participants, position renders as unknown rather than wrong.
- `GameCardJoinButton` gains `openSeats?: number | null` and `queueLength?: number` props; label resolution moves to `gameCardJoinLabel.ts` (pure, tested).
- Ordinal helper `Frontend/src/utils/formatOrdinal.ts` with the locale table; reused by the game page later if wanted (not in scope to change the page).
- No backend logic, no schema, no notification.

## Testing Decisions

- Unit: seat info for 4-max with 2/3/4 PLAYING, queue of 0/1/3, viewer at position 1/2/absent, MIX_PAIRS with viewer gender M/F/unset, EVENT returns nulls, truncated participants return `null` position.
- Unit: join label matrix (open 1/2/3, full with 0/2 waiting, narrow variant) and ordinal formatting for en/ru/ar/ja.
- Component: card renders the suffix only in the scarce cases; badge shows the ordinal; `spotJustOpened` still wins.
- Projection test (`availableGamesCard.projection.test.ts`) asserts `joinedAt` and `status` on participants.
- UI test plan rows: nearly full game on Find, full game with queue, queued viewer on My.

## Out of Scope

- Changing the game page queue panel (already shows position).
- Sorting or highlighting scarce games.
- Push or Telegram copy.

## Further Notes

"2 waiting" is deliberately shown even though it may discourage queueing: an honest number beats a surprise on the game page.
