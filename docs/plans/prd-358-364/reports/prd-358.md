## 2. Deviations from the PRD (with reasons)

- **Tonight removed** (review decision). Padel days are mostly evenings, so an 18:00 cut on today looked identical to Today almost every time, and the only visible signal was the highlight. The row is Today · Tomorrow · Weekend; the time-window overlay, the 22:00 rollover and the "Tomorrow night" label went with it. Consequently no shortcut touches the time slider, and the PRD's `quickShortcutRestore` is unnecessary.
- **The row reflects the calendar** (review decision). The PRD made Today a stateless action that never highlights and Tomorrow / Weekend stored shortcuts with release rules. Instead the highlight is derived from the selected day: Today whenever today is selected (also by default), Tomorrow whenever tomorrow is, Weekend whenever Saturday or Sunday of the coming weekend is (both days listed), so the row and the calendar cannot disagree. The only stored bit is a Weekend pin for a weekend day that is also today, where the tap that got there decides (Weekend sets it, Today clears it). On Friday, tomorrow is Saturday and reads as Weekend.
- **Weekend keeps the calendar** (review decision). The PRD put Weekend in list view, which collapses the calendar like the List toggle. Instead Weekend stays in calendar view with Saturday selected and lists Saturday and Sunday as two date-grouped sections under it, fed by the upcoming query. Switching to List releases it. `findListWeekStartDay` is no longer touched.
- **Placement.** The heading has no go-to-today control to replace (the UI test plan's F-05 was stale). The row is a second line inside the same calendar card, directly under the heading, identical in calendar and list view. No new rail, nothing added to the chip row.
- **`aria-selected` rather than `aria-pressed`.** `SegmentedSwitch` offers arrow keys only in its `tablist` mode, which exposes `aria-selected`. Arrow keys (with the sliding indicator) were kept.
- **Week start.** The resolver takes no week-start input: Saturday and Sunday are the weekend under every week-start preference. The test asserts this.
- **`dayKeys` lives on `filterFindGames` options**, not on `FindFilterState`, because it is a list residual and must not blank calendar day counts.
- **Deep-link catalog.** `?quick=` works through the existing "forward `/find` queries as-is" path in `useDeepLink`. No catalog action was added. Telegram `/play` linking is backend work outside this PRD.
