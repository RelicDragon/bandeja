## 2. Deviations from the PRD (with reasons)

- **`readQueueState` is not called; its rule is re-derived.** The PRD says to reuse it. It reads `game.joinQueues`, which only the game-detail payload carries — on a card it would return `null` for every viewer, every time. `computeSeatInfo` instead re-derives the list from the `IN_QUEUE` participant rows that `computeJoinQueuesFromParticipants` builds `joinQueues` *from*, with the same `joinedAt`-ascending order and the same stable tie-break. A test pins the two functions to the same answer on the same fixture, so the "same ordering as the game page" guarantee is enforced rather than asserted in prose.
- **BAR shows no counts**, though the PRD lists it among the seated types. `BAR_CAPS.unboundedRoster` is `true` and `isPlayingRosterFull` already returns `false` for BAR, so a BAR card's join button never says "queue" and a seat count there would be fiction. The implemented rule is the PRD's own gate (`unboundedRoster === false`), applied consistently.
- **No `truncate` on the label.** The PRD asks for one line; the engagement plan (§2 rule 3) forbids clipping essential information, and an ellipsis eats the count first. The `sm` collapse keeps the label on one line on a 375 pt phone in every locale at normal text size; at the largest accessibility text size it wraps to a second line instead.
- **Contract §0.1/§0.3 (no heavy commands, stay in your file list)** did not apply: this ran as a single session, not a wave, so tests, lint and typecheck were run here through the serialized `./scripts/run-heavy`, and the docs were merged directly, following the precedent set by the PRD 358 report rather than staged under `ui-test-plan/`.
- **One `package.json` line added** (`test:seat-info`) for the same reason.

## 3. Known gaps

- **The Chats row does not repaint on a live queue change.** `ChatListGameCard`'s memo comparator does not look at participants, so a position that changes while the list is on screen updates on the next fetch, not immediately. This is pre-existing — the `In queue` badge itself already behaved this way — and widening that comparator is a chat-list performance decision, not a PRD 359 one.
- `joinedAt` now travels on **every** Find card participant, not only queued ones; Prisma cannot select a column conditionally per row. One `TIMESTAMP(3)` per participant, and nothing the roster does not already expose.
- The game page's own queue panel copy ("You're #2 of 3") was left alone, per Out of Scope.
