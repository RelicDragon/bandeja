## 2. Contract deltas

- **Flag key name.** The PRD's `game.organizerNextActions.enabled` cannot be written: the admin route validates keys against `PLATFORM_SETTING_KEY_PATTERN` (`^[A-Z][A-Z0-9_]{1,63}$`). The key is `GAME_ORGANIZER_NEXT_ACTIONS_ENABLED`; likewise `FIND_LOOKING_COUNT_ENABLED` for 363.
- **Flags endpoint shipped here.** PRD 363 had not landed it when this started; the PRD allows that. The 363 session has since adopted `usePlatformFlags` and `getBooleanSetting`, so there is one mechanism.
- **"Review queue" target.** The PRD says it scrolls to `GameQueuePanel`, but that panel only renders for a *queued* viewer; the organizer's queue list (accept/decline) lives in `GameParticipants`. The button scrolls there. If the list is not on the page (nothing to manage) the action falls back to Invite.
- **Booking action.** "See bookings" needs a bookings section, which only renders when the viewer owns a linked booking. With no linked booking the row reads *Court not booked yet* and its button is **Edit court**, opening the existing Location & time tab, where `hasBookedCourt` and linking live. Still read-only towards providers: nothing here calls one.
- **Booking hint requires a club.** A game with no club has no court to book; `hasBookedCourt === false` there is not a gap. Not in the PRD, but the alternative nags every public-court game.
- **Cost "Settle".** The settle sheet is the debtor's action; the payer/organizer has nothing to settle with themselves. The row shows **Settle** only when the viewer's own share is `UNPAID`, otherwise **Review** (scroll to the ledger, where Remind and the receipt checkboxes are). "Unpaid" counts `UNPAID` non-payer shares; `MARKED_PAID` is the payer's confirmation to make, not a debtor gap, and is not counted.
- **Attendance "within 24 h".** No 24-hour gate exists in the attendance strip today and none was added; the row shows whenever answers are open and someone has not confirmed, exactly like the strip it replaces. Priority order puts it after seats and booking.
- **Entrance animation.** `AnimatedPresencePanel` is a key-swap panel with no exit-to-nothing path; the container uses `AnimatePresence` + a height/opacity `motion.div` with the same `PANEL_TRANSITION` tokens so the block can leave the page when its last row resolves. Reduced motion renders it static.
