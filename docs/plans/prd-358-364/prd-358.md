# PRD 358: PRD: Find day-and-time shortcuts (Today · Tonight · Tomorrow · Weekend)

## Problem Statement

The most common Find question is "what can I play tonight or tomorrow?". Answering it today takes a calendar tap plus the advanced panel's time slider (`FiltersPanel` → `TimeRangeSlider` writing `filterTimeStart` / `filterTimeEnd`). Most players never open the panel, so they scroll a whole day of morning games to find the evening ones. The Find header already has a "go to today" control, but nothing for the two or three moments people actually plan around.

## Solution

Turn the existing "go to today" control in the Find calendar heading into a small segmented group of four day-and-time shortcuts: **Today · Tonight · Tomorrow · Weekend**. Each shortcut sets the selected day and the time-of-day window in one tap using state that already exists (`findSelectedDay`, `filterTimeStart`, `filterTimeEnd`, `findViewMode`). Nothing is added to the entity chip row and no new filter concept is introduced. Shortcuts are transient: they are never persisted, because a persisted "Tonight" is wrong tomorrow.

## Product principle

A shortcut is a preset over existing filters, not a new filter. The advanced panel always shows the truth the shortcut set, and clearing the shortcut restores exactly what was there before.

## User Stories

1. As a player opening Find in the afternoon, I want one tap to see tonight's games, so that I do not scroll past the morning.
2. As a player planning ahead, I want one tap for tomorrow and one for the weekend.
3. As a player who used a shortcut, I want to see which one is active and clear it with one tap.
4. As a player who tweaks the time slider after a shortcut, I want the shortcut to release itself rather than fight me.
5. As a player on a 375 pt phone, I want the group to fit on one line with the month picker.
6. As a Telegram user following a `/play` link, I want `?quick=tonight` to open Find already scoped (nice-to-have).
7. As a developer agent, I want the shortcut resolution to be a pure function with tests across timezones and week starts.

## UX / UI Design

### Placement
- The Find calendar heading row currently holds the month picker and the go-to-today action (`AvailableGamesSection`, calendar header). Replace the single go-to-today control with a `SegmentedSwitch` (existing component) of four options: **Today**, **Tonight**, **Tomorrow**, **Weekend**. On `sm+` the labels are text; on narrow phones the group uses short labels (`Today`, `Tonight`, `Tmrw`, `Wknd`) with full labels as `aria-label`. Minimum 44 px tap targets; the group scrolls horizontally if a locale's labels overflow, never wraps to a second line.
- In list view (`?view=list`) the same group renders above the list, in the position the heading row occupies in calendar view. Same component, same state.

### Behaviour
| Shortcut | View | Selected day | Time window | Notes |
|---|---|---|---|---|
| Today | calendar | today (city TZ) | unchanged | This is the current go-to-today behaviour; it is not an "active" state, it never highlights |
| Tonight | calendar | today | 18:00–24:00 | If local hour ≥ 22, Tonight targets tomorrow 18:00–24:00 and the label reads "Tomorrow night" |
| Tomorrow | calendar | tomorrow | 00:00–24:00 | |
| Weekend | list | next Saturday (or today if today is Sat/Sun) | 00:00–24:00 | `findListWeekStartDay` = that Saturday; a day-set residual keeps only Sat+Sun rows |

- Exactly one of Tonight / Tomorrow / Weekend can be active; Today is an action. Tapping the active shortcut clears it: the time window returns to the value captured when the shortcut was applied and the day stays where the user left it.
- If the user changes the time slider, the selected day, or the view while a shortcut is active, the shortcut deactivates silently (the preset is no longer what is shown).
- Re-tapping the Find tab (existing `requestFindGoToCurrent`) clears any active shortcut, as it already resets to today.
- "Today" is decided in the **Home city timezone**, the same clock Find already uses for day cells.

### Empty results under a shortcut
- The existing `EmptyStateCard` title reads "No games tonight" / "No games tomorrow" / "No games this weekend" instead of the generic message. Recovery actions are PRD 363; this PRD only sets the title.

### Accessibility and locales
- Segmented group uses the existing APG arrow-key behaviour of `SegmentedSwitch`. Active shortcut exposes `aria-pressed`. Copy for the four labels, short labels, and three empty titles in all 11 locales; RTL verified for `ar`.

### Motion
- Selecting a shortcut animates the day change with the existing calendar day transition; the list uses the existing `AnimatedGameList` presence. No new motion.

## Implementation Decisions

- New pure module `Frontend/src/components/home/findQuickShortcuts.ts`: `resolveQuickShortcut(kind, { now, timezone, weekStartDay })` → `{ view, selectedDay, timeStart, timeEnd, dayKeys? }`, and `isShortcutStillApplied(state, resolved)` for the silent-release rule. No React in this file.
- State: a new non-persisted field on the Find store (`activeQuickShortcut: 'tonight' | 'tomorrow' | 'weekend' | null`, plus `quickShortcutRestore: { timeStart, timeEnd } | null`). It is **excluded** from the IndexedDB persist whitelist in `useGameFilters.ts`. Optional URL sync `?quick=` via `useUrlStoreSync`, read-only on load (deep link in), never written on every change.
- Weekend needs a residual day-set filter: extend the client FindFilter module (the same place the time-of-day residual lives) with an optional `dayKeys: string[]`. No backend change; the list query already spans from the week start.
- Reuse `SegmentedSwitch` from `Frontend/src/components`. Do not create a new chip primitive.
- No backend, no schema, no notification.

## Testing Decisions

- Unit: `findQuickShortcuts.test.ts` — Tonight before/after 22:00, Tomorrow across month end, Weekend from Mon/Fri/Sat/Sun, DST day in a `Europe/Belgrade` and an `Asia/Bangkok` city, week-start Monday vs Sunday, release rule when slider/day/view change.
- Component: heading group renders four options, one active at a time, clear-on-retap restores the captured window, list view renders the group above the list, empty title changes per shortcut.
- Persist test: `useGameFilters.persist.test.tsx` gains a case asserting `activeQuickShortcut` is never written.
- UI test plan rows (`docs/UI_TEST_PLAN.md`): Tonight on a busy day, Weekend from a weekday, clear shortcut, re-tap Find tab.

## Out of Scope

- New chips in `EntityFilterChips` (fixed five-up row; leave it).
- Persisting shortcuts, or a "this week" range.
- Backend time filtering (stays a client residual).
- Recovery actions in the empty state (PRD 363).

## Further Notes

The decision to use the calendar heading instead of the chip row is deliberate: Tonight and Tomorrow are day jumps, so they belong next to Today. The chip row keeps its equal-width layout on small phones.
